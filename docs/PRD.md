# 项目需求文档（PRD）— 教育互动训练系统（E.I.Art）

> 目标：交接时让接手人快速理解**要做什么**、**为什么这么做**、**系统由哪些端组成**、**每块功能是否已完成**、**后续迭代顺序**。
>
> 说明：本文基于当前仓库实现与现有文档整理，偏“落地可执行”，不是论文式描述。

---

## 1. 背景与问题

本项目面向教育/康复训练场景，要求教师对学生进行分课程训练（命名、拟声、模仿、配对、排序等），在训练过程中：

- 教师端需要**选择学生、选择课程与子项、发起训练、控制流程**（下一项/提示/表扬/提问等）。
- 儿童端需要**展示课程内容**（图/音/视频/互动小游戏）、并在训练时采集摄像头/麦克风数据。
- 服务端需要管理**会话生命周期、录制与存储、分析与比对、反馈与触发动作**；并支持可选的机械臂/表情展示等外设联动。

该系统的关键挑战：

- 多端协同（教师端、儿童端、服务端）实时性要求高（Socket.IO）。
- 媒体采集、录制、分析流水线与 UI 播放节奏要一致。
- 可插拔分析：既要能用 Mock 先跑通流程，也要能切换真实模型（MediaPipe、ASR 等）。

---

## 2. 项目目标（交付定义）

### 2.1 核心交付（必须）

1. 教师端能完成“登录→选学生→选课/选子项→开始训练→控制流程”的完整闭环。
2. 儿童端能在会话驱动下，正确展示并播放资源，且按需采集音视频并上传。
3. 服务端能稳定管理会话，完成录制、（可选）分析/比对，并将结果/事件反馈给教师端与儿童端。
4. 工程可交接：文档清晰、环境可复现、无明显“死文件/死路由/死说明”。

### 2.2 迭代交付（可选增强）

- 真实模型推理（姿态、注意力、语音识别）达到可用精度与性能。
- 训练结果结构化统计与可视化（按学生/课程/时间）。
- 外设联动（机械臂动作、表情展示、音频策略等）。

---

## 3. 用户与角色

- **教师/治疗师（Teacher）**：配置与控制训练流程、查看结果。
- **儿童（Child）**：被动接收展示与互动；采集音视频。
- **系统管理员/开发者（Admin/DevOps）**：部署、配置、维护资源与数据库、导入课程。

---

## 4. 端与组件划分（实现约束）

### 4.1 服务端（Flask + Socket.IO）

- 入口：`app.py`
- 职责：
  - HTTP：页面/接口（`/child`、`/courses`、`/api/*` 等）
  - Socket：会话房间、播放指令、媒体上行（video_frame/audio_chunk）、结果下发
  - 会话：`app/session/`
  - 录制：`app/recorder/` + `app/services/media_service.py`
  - 分析框架：`app/core/`（registry/auto_register/pipelines/matchers/analyzers/trigger）
  - 反馈：`app/services/feedback_service.py`
  - 存储：`app/storage/`

### 4.2 儿童端（传统 HTML/JS）

- 页面：`templates/child.html`
- 脚本：`static/js/child.js`（普通网页方式运行，PWA 已移除）
- 职责：
  - 接收服务端的播放指令
  - 播放资源（图片/视频/音频/互动 iframe）
  - 采集摄像头/麦克风并上行至服务端

### 4.3 教师端（现代前端）

- 目录：`teacher_frontend/`（Vite + React）
- 职责：
  - 登录与学生管理
  - 选课与子项选择
  - 训练控制台（课程播放控制、辅助按钮、结果展示等）
  - 与后端通信：REST + Socket.IO

### 4.4 可选：机械臂/表情/外设

- 后端模块：`app/robot/`
- 独立 Node 子系统：`doll/`（如果需要）

## 5. 主要业务流程（用户故事）

### 5.1 教师端发起训练（主流程）

1. 教师登录（账号/密码）。
2. 选择学生（或新建/编辑学生信息）。
3. 选择课程类型与课程（可多选子项）。
4. 开始训练：后端创建会话 sessionId；教师端进入控制页。
5. 教师点击“播放/下一项/提示/表扬/提问”等：
   - 后端通过 Socket 广播/下发指令到儿童端（按 session room 隔离）。
6. 儿童端展示内容并上行媒体流：
   - 服务端录制、分析（可选）、比对（可选）。
7. 服务端将匹配结果/分析结果/触发动作反馈：
   - 教师端显示状态、分数、摘要等。
8. 结束训练：会话关闭、落盘、写入数据库训练记录（若启用）。

### 5.2 儿童端互动课（配对/排序）

- 儿童端通过 iframe 打开 `static/resources/interactive/*.html`，由教师端/服务端下发课程级别参数驱动。
- 排序/配对也可通过 `/sequencing`、`/matching` 路由重定向访问静态页（对齐儿童端行为）。

## 6. 功能需求（Functional Requirements）

> 每条需求以“验收口径”描述，便于交接验收。

### 6.1 账号与权限

- **FR-ACC-001 教师登录**
  - 验收：教师端可使用管理员账号登录；后端能校验密码并返回身份信息。
- **FR-ACC-002 教师注册/管理（可选）**
  - 验收：可创建教师账号（若开放）；可查看教师列表（后台接口）。

### 6.2 学生与档案

- **FR-STU-001 学生管理**
  - 验收：教师端可创建/查看/编辑学生基本信息；后端持久化到 SQLite。
- **FR-STU-002 能力项记录**
  - 验收：训练后能更新/写入能力项分数（按能力类型维度）。

### 6.3 课程体系与资源

- **FR-CRS-001 课程/子项结构**
  - 验收：后端 `/courses` 返回课程与子项，教师端可浏览与选择。
- **FR-CRS-002 资源组织与路径规则**
  - 验收：课程项能引用 `static/resources/` 下的图片/音频/视频/互动页；儿童端能正确加载播放。
- **FR-CRS-003 资源导入工具（可选）**
  - 验收：支持从 CSV/目录结构批量导入课程资源与数据库记录。

### 6.4 训练会话与控制

- **FR-SES-001 会话创建/开始/结束**
  - 验收：开始训练生成 sessionId；结束训练后会话状态正确；不会串台。
- **FR-SES-002 房间隔离**
  - 验收：同一时间多会话互不干扰；教师/儿童进入各自房间后只收到本会话事件。
- **FR-CTL-001 播放控制（下一项/跳转）**
  - 验收：教师端控制播放节奏，儿童端按指令切换展示资源。
- **FR-CTL-002 辅助按钮（提示/表扬/提问）**
  - 验收：按钮触发后能播放相应语音/动作（至少语音通）。

### 6.5 媒体采集、录制与存储

- **FR-MED-001 摄像头/麦克风采集（儿童端）**
  - 验收：儿童端获取权限，能采集并向后端发送视频帧与音频块。
- **FR-MED-002 服务端录制与落盘**
  - 验收：每个会话生成对应录制文件/结果文件目录；异常能恢复或至少不崩溃。
- **FR-MED-003 清理与容量控制（可选）**
  - 验收：过期会话与临时文件能按策略清理。

### 6.6 分析与比对（可插拔）

> 采用 registry + mode（mock/real）切换；配置由 `config/analyzers.yaml` 与环境变量控制。

- **FR-ANL-001 分析器注册与切换**
  - 验收：启动时自动注册；可按配置在 mock/real 之间切换；real 不可用时回退 mock。
- **FR-ANL-002 姿态分析与比对**
  - 验收：能输出关键点/匹配分数；可配置阈值；结果能反馈到教师端。
- **FR-ANL-003 注意力分析（可选）**
  - 验收：输出注意力指标或窗口统计；结果可反馈。
- **FR-ANL-004 语音识别/比对（可选增强）**
  - 验收：mock 可跑通流程；real ASR 需安装 torch/funasr/librosa，并能输出识别文本与评分。

### 6.7 语音系统（播放与策略）

- **FR-AUD-001 语音清单与选择策略**
  - 验收：从 `config/audio_manifest.yaml` 读取条目；按 entry_id 或策略选择资源。
- **FR-AUD-002 播放控制（开始/停止/状态上报）**
  - 验收：教师端可停止；儿童端能回传播放状态（进度/错误）；多会话隔离。

### 6.8 机械臂与外设（可选）

- **FR-RBT-001 机械臂控制 API/事件**
  - 验收：后端 blueprint 可用；能接收触发并播放动作（若部署外设）。

## 7. 非功能需求（Non-Functional Requirements）

- **NFR-001 可部署/可复现**
  - 约束：`docs/ENVIRONMENT.md` 可按步骤跑通；依赖拆分合理（主依赖 vs 可选重型依赖）。
- **NFR-002 稳定性**
  - 约束：Socket 断线/重连不崩；会话与房间隔离；异常日志可定位。
- **NFR-003 性能**
  - 约束：本地局域网下播放指令到展示延迟可接受；分析可按采样率降低负载。
- **NFR-004 可维护性**
  - 约束：文档入口清晰；无明显死路由/死模板；一次性脚本归档到 `tools/maintenance/`。
- **NFR-005 安全（最小）**
  - 约束：生产环境不使用默认 SECRET_KEY；默认账号需提示修改；不要提交 `.env`。

## 8. 数据与配置需求

- **数据库**：SQLite（`database/app.db`），模型在 `database/models.py`。
- **课程数据来源**：优先数据库；无数据时可回退 `static/courses.json`（兼容）。
- **分析器配置**：`config/analyzers.yaml`（示例：`config/analyzers.yaml.example`）。
- **语音清单**：`config/audio_manifest.yaml`。
- **环境变量**：见 `app/config.py` 与 `docs/ENVIRONMENT.md`。

## 9. 接口与事件（简要）

### 9.1 HTTP（示例）

- `GET /courses`：获取课程与子项
- `GET/POST /api/students`：学生管理
- `POST /api/teacher/login`：登录

### 9.2 Socket.IO（示例）

- `play_resource`：教师端 → 服务端 → 儿童端（播放资源与 aux）
- `video_frame` / `audio_chunk`：儿童端 → 服务端（媒体上行）
- `analysis_result` / `match_result` / `audio_status_update`：服务端 → 教师端（反馈）

> 详细事件表建议后续在 `docs/ARCHITECTURE.md` 增补为“事件字典”，便于交接调试。
