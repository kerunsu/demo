# 儿童端内容呈现逻辑修改规划

## 需求概述

本次开发涉及三个儿童端内容呈现相关的功能优化：

1. **初始等待界面优化**：摄像头显示3秒后全屏展示FG.png待机图片
2. **表扬功能增强**：表扬按钮触发语音+视频动画，动画结束后自动下一个+自动提问
3. **自动提问语音**：内容呈现时自动播放"提问"语音

## 功能二：表扬功能增强

### 当前行为

1. 教师点击"表扬"按钮
2. 发送 `play_resource` 事件（带 `aux: { praise: true }`）
3. 儿童端播放表扬语音（通过音频系统）

### 目标行为

1. 教师点击"表扬"按钮
2. 儿童端：
   - **同时** 播放表扬语音
   - **同时** 随机播放一个表扬视频动画（从 `static/resources/videos/praise/` 选择）
3. **视频播放结束后**：
   - 自动切换到下一个 item
   - 自动播放"提问"语音

### 涉及资源

- **表扬视频**：`static/resources/videos/praise/001.mp4` ~ `009.mp4`（共9个）
- **表扬语音**：通过现有音频系统播放（`audio_manifest.yaml` 中 `praise_correct` 等条目）

### 实现方案

#### 方案选择（调整为符合项目规范）

**统一方案（推荐）**：后端负责资源管理与选择，前端只负责播放
- **后端** 根据配置选择表扬视频路径（类似课程资源与语音的后端解析机制）
- **前端** 不保存路径列表，只消费后端下发的 `praiseVideo` 路径
- **视频结束后** 仍采用前端联动方式通知教师端进行“下一个 + 自动提问”

理由：
- 路径与随机选择逻辑集中在后端，符合“资源路径由后端维护”的规范
- 不引入复杂的后端状态机，只增加轻量配置与选择逻辑

#### 修改文件

1. **`config/praise_videos.yaml`**（新增）：表扬视频资源清单或目录配置
2. **`app/utils/resource_utils.py`**：复用/扩展随机选择逻辑，支持视频扩展名
3. **`app/sockets/handlers.py`**：在 `aux.praise` 处理时选择视频路径并返回
4. **`app/sockets/events.py`**：转发 `praiseVideo` 字段给儿童端
5. **`static/js/child.js`**：接收后端路径并播放视频
6. **`teacher_frontend/components/ControlPage.tsx`**：监听视频结束事件，自动切换

def handle_praise_video_ended(data):
    """表扬视频播放结束事件 - 转发给教师端"""
    session_id = data.get('sessionId')

## 风险与注意事项

### 功能一
- **摄像头权限**：如果用户拒绝摄像头权限，定时器仍应触发待机图片
- **待机图片加载**：考虑预加载图片避免闪烁

### 功能二
- **视频自动播放**：浏览器可能阻止自动播放带声音的视频，建议视频静音或使用用户交互触发
- **视频结束事件可靠性**：`onended` 事件在某些情况下可能不触发，需要添加超时备份
- **并发问题**：快速连续点击表扬按钮可能导致多个视频同时播放，需要加锁

### 功能三
- **重复播放**：如果教师多次点击同一内容项，会重复播放提问语音，可能需要节流
- **配对/排序课程**：这些课程可能不需要提问语音，需要按课程类型判断
