# 项目重构 Agent 执行规范

## 1. 项目概要与核心需求

本项目是面向教师端、儿童端和控制/监控端的机器人课程互动系统，后端使用 Flask、Flask-SocketIO、SQLAlchemy/SQLite，前端使用 React/Vite，并包含浏览器与 Robot Runtime 的音视频采集、课程播放、语音对话、动作表情、评分分析和 session 数据归档。

本次工作是渐进式重构，不是重写。最高原则是：**现有功能、页面效果、操作流程、HTTP/Socket 契约、录制生命周期、文件名、时序和降级行为全部保持不变**。不得更换框架、强拆微服务或要求旧数据一次性迁移。

核心需求：

- 所有工作按以下优先级决策：①已有功能与数据安全；②稳定性与可恢复性；③模块化与可维护性；④控制端可配置能力；⑤性能优化。低优先级目标不得牺牲高优先级目标。
- 软件可在教师端、儿童端和控制/监控端长期稳定运行。
- 六个业务模块边界清晰，只通过稳定接口通信，修改单个模块尽量不影响其他模块。
- 环境摄像头和环境麦克风支持 `0..N` 台，可在控制端发现、增减、启停、预览、设置必需/可选及主设备。
- 正式采集前必须完成模块与设备自检；所有必需项通过后才允许原子启动，失败时完整回滚。
- 动作库和表情库支持安全的批量导入、校验、预览、版本管理和回滚。
- 课程交互按“课程 → 事件 → 情境 → 台词 → 动作/表情/语音及时序”配置，可快速增加课程、事件、情境、台词、素材和分析模型。
- 新配置必须兼容旧课程硬编码逻辑；未配置、未发布或解析失败时完整回退旧行为。
- 多设备数据使用统一时间轴和合理的数据结构保存，便于后续检索、对齐和分析。
- 控制端应能查看设备、轨道、录制、存储容量、文件完整性、时间同步偏差和模块健康状态，并能定位每次降级的原因。

## 2. 项目目标

1. 在不改变产品行为的前提下，降低耦合、重复代码和全局可变状态。
2. 建立稳定接口、明确依赖方向、统一生命周期与错误处理。
3. 实现可配置、可校验、可预览、可发布、可回滚的课程和交互资源管理。
4. 使采集设备、算法模型、ASR/LLM/TTS、动作和表情均可通过适配器扩展。
5. 保证录制、课程、行为和分析事件共享统一 session 标识及单调时间轴。
6. 形成具备测试、文档、部署说明、故障排查和验收记录的可交付软件。

## 3. 目标架构

项目按以下六块组织；允许设置轻量 `contracts` 目录保存 DTO、Protocol、事件信封和错误类型，但不得形成新的业务模块。

### 3.1 前端 Web

负责教师端、儿童端、控制/监控端 UI，只调用 HTTP/Socket 接口。不得直接依赖数据库、服务端文件路径、设备驱动或模型实现。

控制端新增能力应集中为三类：设备与采集管理、多模态 session/轨道可视化、课程交互编排。交互编排允许选择固定语音、TTS 台词、动作、表情及各自时序，并显示最终命中来源和回退路径。

### 3.2 后端门面

负责 Flask 路由、Socket 事件、输入校验、DTO 转换、权限与会话编排入口。门面只接线，不实现采集、落盘、评分、课程决策、模型推理和对话主链路。

### 3.3 采集

负责浏览器、服务器及 Robot Runtime 的设备发现、自检、采样、上行、补传、背压和生命周期管理；不决定最终存储路径、课程逻辑、评分或 LLM 行为。

### 3.4 存储

负责 sessions、SQLite、meta、timeline、媒体轨道、行为、结果和报告的读写；课程 CSV/YAML/静态媒体作为只读内容库管理。所有文件布局、原子写入、版本和兼容读取由本模块负责。

### 3.5 计算

负责 readiness、评分、课程推进、题目窗口、注意力、情绪、动作决策、分析模型与报告计算，不包含对话 LLM 主链路。新增模型必须实现统一输入输出接口，并支持超时、降级和可观测性。

### 3.6 语音对话

负责唤醒、ASR、对话上下文、LLM、TTS 和话术编排。输入为音频、文本和稳定上下文，输出为文本、稳定 `lineId` 及播报指令，不直接操作 UI、数据库或设备。

依赖方向应由门面调用用例，用例依赖接口，基础设施实现接口。禁止领域代码反向依赖 Flask、SocketIO 或具体硬件 SDK。

## 4. 兼容性与交互规则

- 保持现有页面 URL、UI 表现、按钮、操作顺序、HTTP 方法/状态码/JSON 字段、Socket 事件名/payload/ack/room 和 Runtime 契约。
- 保持 `python app.py`、默认端口、现有脚本及旧 import 入口可用。
- 一场训练只正式开始和停止录制一次；切换课点只追加 timeline，不重启录制。
- 保持 `video.avi`、`audio.wav`、`video.environment.avi`、`audio.environment.wav`、`timeline.csv`、`session_meta.json` 等既有名称和旧数据可读。
- 第一台主环境设备继续使用兼容文件名；额外环境轨道使用稳定 `trackId` 命名，并登记在 `session_meta.tracks[]`。
- `prepare_training` 只能预留标识和计划。所有启用且必需的设备、Runtime、模型、磁盘和课程资源通过自检，且验证首帧/首音频块后，才可提交正式开始；失败必须停止已启动资源并禁止进入课程。
- 环境设备未配置时记为 `disabled/not_configured`，不能伪报成功或失败。训练开始时冻结设备配置，训练中修改仅对下一场生效。
- 新交互使用稳定事件键，例如 `question.naming`、`question.vocal_imitation`、`question.ordering`、`question.pairing`、`praise`、`hint`、`retry`、`greeting`、`farewell` 等；不得以可变中文台词全文作为主键。
- 旧 `aux.question` 必须由统一兼容适配器按课程类型转换为新事件，同时保留旧解析结果。新绑定支持 `disabled`、`inherit`、`replace`：默认 `inherit`，仅覆盖明确配置字段；未命中或异常时使用完整旧结果，不能返回半套行为。
- 新配置采用 `draft → validate → preview → publish → rollback`。每场 session 冻结已发布版本，编辑草稿不得改变进行中的课程。
- 动作、表情和语音继续使用同一 `behaviorId/requestId` 与现有原子播放屏障；必需语音失败时不得单独播放动作或表情。

### 4.1 统一降级规则

所有新增能力必须位于兼容开关或适配器之后，旧路径在新路径通过完整验收前不得删除：

- 新交互配置、资源解析或控制端新页面不可用：继续使用旧 `course_map`、旧接口和旧控制入口。
- 新动作、表情或语音素材缺失/损坏：使用该 session 已冻结版本中的旧素材与旧时序，禁止拼出半套行为。
- 新分析模型异常：优先回退原模型；没有原模型时，optional 能力返回明确 `degraded/no-data`，required 能力按既有门禁阻止开始。
- 新增环境设备异常：optional 轨道允许跳过并记录原因；required 轨道必须阻止正式采集，不得假装成功。
- 新存储索引或可视化不可用：既有 session 落盘路径必须继续工作；若无法保证主媒体安全写入，则在正式开始前失败，而不是边录边丢数据。
- 降级不得静默发生。日志、session 元数据和控制端应记录触发原因、原路径/新路径、所用版本、时间和影响范围。
- 每个新模块都必须具备独立关闭开关、健康检查、超时和回退测试；回退本身失败时必须显式报错并进入安全状态。

## 5. 代码规范

1. 修改前先阅读相关实现、测试、配置和调用链，记录当前分支、HEAD 与 `git status`，不得覆盖用户已有改动。
2. 先用特征测试或契约测试固定现有行为，再做小步、可验证、可回滚的迁移。禁止一次性搬迁整个项目。
3. 单文件、类和函数保持单一职责；公共接口使用明确类型、DTO 和领域错误，避免无约束字典跨层传播。
4. 路由和 Socket handler 只做校验、鉴权、转换与调用；业务规则不得散落在入口层。
5. 禁止新增跨模块内部实现引用、循环依赖、隐藏全局状态和导入即执行的副作用。
6. 线程、设备、文件和连接必须有明确所有者；`start/stop/close` 应幂等，并保证异常路径释放资源。
7. 外部设备、文件、网络和模型调用必须设置超时、错误分类、必要重试、取消与可观测日志；不得静默吞错。
8. 配置和标识使用稳定英文键；界面文案可本地化。新增字段必须版本化，并提供旧数据默认值。
9. 删除代码前必须确认没有静态引用、动态导入、配置引用、脚本入口和外部调用，并保留可恢复路径。
10. 性能优化必须有指标或 profile 证据，不得以降低采样率、音画质量、模型能力或交互准确性换取速度。
11. 每个改动运行最小相关测试，阶段结束运行 `python -m pytest tests -q`；不得通过删除测试、放宽断言或伪造成功完成任务。

## 6. 存储规范

- 以 `sessionId/mediaSessionId/trainingSessionId` 建立稳定关联，所有媒体、课程、行为和分析记录使用同一单调时间基准，并记录墙上时钟映射。
- 既有目录和文件名保持兼容；新增结构通过 schema/version 字段扩展，读取器必须兼容历史版本。
- `session_meta.json` 的轨道记录至少包含 `trackId`、`deviceId`、类型、角色、所有者、必需性、文件名、格式、开始偏移、结束状态和质量信息。
- `timeline.csv` 持续记录课点、事件及时间范围；切题只追加记录，不生成新的主录制文件。
- 文件采用临时文件加原子替换，数据库事务与文件提交需要明确的一致性策略；失败不得留下被当作成功数据的半成品。
- 素材使用稳定 `assetId + version`，记录类型、显示名、文件名、校验和、时长、格式、标签、兼容性和引用关系。发布中的版本不得被物理删除。
- 批量上传先进入 staging，校验 schema、MIME/magic、大小、重复项、路径穿越和压缩炸弹，再预览并原子提交；默认冲突策略为跳过，禁止静默覆盖。
- 课程和交互配置使用稳定 `courseId/itemId/eventKey/sceneKey/lineId` 引用；运行数据保存所用配置版本，确保结果可追溯和复现。
- 日志不得记录密钥、完整令牌或不必要的儿童隐私数据；敏感信息遵循最小化、脱敏和访问控制原则。

## 7. 透明执行与交付

Agent 必须持续透明，不得只回复“已完成”。

开始任务时说明：

- 对需求的理解、预计修改范围和明确不修改的部分；
- 发现的脏工作区、风险、兼容点与验证计划。

执行过程中说明：

- 当前正在处理的模块；
- 新发现的重要事实、与原计划的差异及采用的兼容策略；
- 阻塞、测试失败或需要用户决策的事项。未经授权不得扩大任务范围。

完成任务时必须报告：

- 修改、新增、删除了哪些文件及其用途；
- 行为和数据结构发生了什么变化，哪些外部契约确认未变；
- 执行了哪些测试、测试结果和未执行项目；
- 已知风险、兼容回退方式和建议的下一步。

不得声称未经验证的功能已经完成。涉及删除、数据迁移、覆盖配置或外部系统写入时，必须先确认范围并提供恢复方案。

每个阶段只有在“阶段范围内测试通过、旧路径仍可运行、回退演练通过、文档与差异报告完成”后才能进入下一阶段。基线测试若原本失败，必须先记录并隔离；新增失败不得带入下一阶段。禁止多个子智能体同时修改同一核心文件或同一契约。

## 8. 文档维护

- 代码、接口、配置或存储结构变更时，同一任务内同步更新对应文档，不允许文档长期滞后。
- `README.md` 只保留安装、启动、入口、最短使用流程和文档索引。
- 架构文档记录六块职责、依赖方向、关键流程和扩展点；接口文档记录 HTTP/Socket/Runtime 契约及兼容策略。
- 存储文档记录目录、文件命名、schema 版本、时间轴、示例和迁移/回滚方法。
- 运维文档记录部署、配置、自检、日志、备份、恢复和常见故障排查。
- 重要架构决策使用 ADR，说明背景、选择、替代方案、影响和回滚方式。
- 合并重复或失效文档前先核对代码；无法确认的内容标记“待验证”，不得凭猜测改写事实。

## 9. 完成标准

只有同时满足以下条件，重构任务才可标记完成：既有测试和新增测试通过；三端表现与外部契约无未批准变化；旧数据库、课程、素材和 sessions 可读；录制生命周期与时间轴正确；控制端可查看设备/轨道/存储/同步和降级状态；必需设备自检失败时不会开始正式采集；新配置未发布或异常时可完整回退；关闭全部新功能开关后旧主流程仍可运行；文档与实现一致；最终交付报告清楚列出改动、验证、风险和回滚方法。
