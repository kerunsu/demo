# 教师端开课与机器人多模态同步重构需求

## 1. 目标

本次重构解决两个直接影响课堂使用的问题：

1. 教师点击开课后，系统必须以“本场录制已经真实开始并收到有效数据”为唯一放行条件，快速、稳定地进入控制界面。
2. 机器人从待机切换到提问、提示、表扬等状态时，语音、动作、表情和儿童端动画必须作为同一个行为完整播放，并在全部模态结束后无缝回到待机。

稳定录制和顺畅开课是 P0；多模态完整同步是 P0。注意力、情绪、资源预取等增强能力不得阻塞这两个主流程。

## 2. 当前问题

- 开课准备把连接、采集、注意力、情绪、课程、图片、语音和设备 8 项全部设为硬门禁，任一项没有回报都会让页面长期停留在“检测中”。
- 界面显示“探针”等内部术语，教师无法据此判断故障原因或采取有效操作。
- 语音准备会实际试播音频，并等待儿童端点击解锁声音，既会突然发声，也会造成无限等待。
- 严格预检在增强检查完成后才启动正式采集，形成“先等非关键检查、后验证录制”的错误优先级。
- 行为的语音在动作/表情提交前已经下发，缺少共同开始时刻，可能出现语音先响、动作和表情后启动。
- 行为结束依赖多个分散的计时和回调；待机动作还有额外延迟，容易出现空档。

## 3. 开课准备需求（P0）

### 3.1 唯一硬门禁

- 唯一硬门禁是 M2“录制与采集”。
- 放行必须有真实证据：录制会话存在、采集已启动，并且服务端已收到该会话的有效视频帧或音频数据块。
- 仅有客户端布尔值、预检图片或“正在录制”声明不能伪造成功。
- 正式采集启动失败、目标儿童端无法定向通知或有效数据超时，必须阻止开课，并显示可操作的具体原因。

### 3.2 非阻塞诊断

- 连接、注意力、情绪、课程清单、图片资源、语音缓存和附加设备均为诊断项。
- 诊断项可以在后台继续执行；失败或超时统一记录为“已降级”，不得阻止进入控制界面。
- 用户界面不得使用“探针”作为主文案，应改为“后台诊断”，并明确提示其“不影响开课”。
- 诊断状态需保留模块、原因、失败资源和时间信息，供调试查看；不得只显示无限旋转图标。

### 3.3 静音准备

- 开课准备阶段禁止播放任何 TTS、音频文件或测试音。
- 音频准备只允许静默下载、解码或缓存；浏览器声音解锁应在真正需要播放课程语音时处理，不作为开课门禁。
- 不得在准备流程中显示或等待“点击解锁声音”的遮罩。

### 3.4 时序与恢复

- 严格预检模式应先发起正式采集，再并行运行非关键诊断。
- 收到首个有效采集数据后立即放行，不等待其他模块。
- 同一训练会话的重复请求必须幂等；旧 generation 的迟到回报不得改变新一轮状态。
- 超时后：录制未就绪则明确失败并允许重试；仅诊断未完成则自动降级，不得卡住。
- 教师不再需要“强制进入”来绕过非关键检查；任何绕过都不能绕过真实录制门禁。

## 4. 多模态状态播放需求（P0）

### 4.1 单一行为事务

- 每次待机→提问/提示/表扬/社交等切换生成唯一 `behaviorId` 和 `requestId`。
- 语音、机械动作、机器人表情、儿童端行为动画必须携带相同标识，迟到或不匹配的完成事件不得释放当前行为。
- 必需语音无法下发时，整组行为在任何视觉模态显示前取消，禁止只播放动作或表情。

### 4.2 同步开始

- 服务端为每个行为计算一个短暂的共同开始锚点。
- 语音使用锚点剩余时间作为延迟；动作和表情等待同一锚点后启动。
- 网络或服务端处理耗时不得被重复叠加为多个串行延迟。
- 首次触发与后续触发走同一套事务和幂等逻辑，不允许首条事件被初始化、待机回归或旧回调吞掉。

### 4.3 最长模态结束边界

- 一个行为的完成时刻为以下模态实际或可靠估算结束时刻的最大值：语音、机械动作、机器人表情、儿童端动画。
- 任一模态提前结束不得提前释放行为锁或切回待机。
- 完成回调必须校验 `behaviorId + requestId + sessionId`（适用时）并具备幂等性。
- 模态异常必须有有限超时并标记降级，避免永久卡死；超时不得让旧回调释放新的行为。

### 4.4 无缝回待机

- 最长模态结束后立即恢复待机表情/动作，不增加人为等待。
- 待机媒体应预先加载并持续在底层可用，切换时不得出现空白帧或闪烁。
- 新行为开始时必须取消尚未执行的待机回归，避免待机动作覆盖正式动作。

## 5. 可观测性与调试

- 开课状态至少提供：训练会话、录制会话、关键门禁状态、最后一次有效采集时间、非关键降级项及原因。
- 行为日志至少提供：`behaviorId`、`requestId`、共同开始锚点、各模态计划/完成时间、最终最长模态、是否降级。
- 面向教师的提示使用业务语言；内部错误码可保留在日志和详细诊断中。
- 所有等待必须有明确所有者、完成条件和有限超时。

## 6. 验收标准

1. 准备阶段全程无测试音、TTS 或资源试播。
2. 注意力、情绪或资源预取失败时，只要录制证据成立，教师仍能立即进入控制界面。
3. 录制未启动或服务端未收到有效数据时，不能进入控制界面，并能看到明确原因和重试入口。
4. 严格预检不会因等待分析或资源检查而延迟正式采集启动。
5. 连续重复开课、断线重连和迟到回报不会复用错误会话或错误 generation。
6. 提问、提示、表扬至少各验证一次：语音、动作、表情按共同锚点启动，任何短模态结束后仍等待最长模态。
7. 不相关或重复的音频/动画完成回调不能提前释放当前行为。
8. 行为完成后立即回到待机，无额外 500 ms 空档；下一次点击可立即进入新的完整事务。
9. 前端构建、相关后端回归测试和新增的门禁/同步测试全部通过。

## 7. 不在本次范围

- 不更换 Flask、Socket.IO、React 或现有机器人 Runtime。
- 不改变既有课程、录制文件命名和历史 session 读取契约。
- 不降低录制采样率、画质或音质来换取表面速度。
- 不删除注意力、情绪或资源诊断能力，仅调整其优先级和阻塞关系。

## 8. 全链路精确时间轴与对话控制补充需求

### 8.1 全链路日志（P0）

- 在保留录制章节 `timeline.csv` 和题目状态机 `interaction_timeline.jsonl` 的同时，每场课程的录制目录新增 `full_interaction_timeline.jsonl`，与该课程的 `video.avi`、`audio.wav`、`session_meta.json` 同目录保存，不得另建以内部 UUID 分类的查看目录。
- 所有记录以服务端墙上时钟和单调时钟为权威，并保存严格递增的 `sequence`；客户端时间只作为偏移分析元数据。
- 覆盖教师端操作、儿童端操作、课程下屏提交/失败、对话输入/回复，以及机器人语音、动作、表情、儿童动画的排队、下发、开始、完成、降级与失败。
- 每条记录尽可能关联 `trainingSessionId/sessionId/questionId/requestId/behaviorId`，使控制命令、实际执行和完成回执可在同一时间轴核对。
- 不保存原始音视频 Base64、凭据或令牌；仅保存媒体长度与校验摘要，文本和普通业务载荷做长度限制。
- 教师端不显示日志查看或导出入口，避免干扰课堂控制；日志直接按课程录制文件夹查看，服务端查询接口仅供 Server 运维和自动化测试使用。

### 8.2 教师端唤醒与儿童端窗口（P0）

- 智能体默认由当前主控教师点击“唤醒智能体”触发；手动唤醒不得播放确认音。
- 唤醒词能力保留，但默认关闭，并可在 Server 配置中心持久化开启；关闭时环境声音不得触发唤醒。
- 教师端可按当前训练会话显示或隐藏儿童端对话窗口；隐藏只改变 UI，不停止课程录制。
- 唤醒和窗口命令必须经过教师主控租约鉴权、精确定向到当前儿童会话并返回成功/失败确认；旁观教师不得写入。
- 儿童端重连后主动读取窗口可见性和唤醒词配置，避免界面状态与 Server 实际状态不一致。

### 8.3 补充验收标准

1. 一次“提问→下屏就绪→语音/动作/表情执行→最长模态完成”可按关联 ID 在该次课程录制目录的同一日志文件中还原。
2. 原始音视频和凭据不会出现在日志中；并发写入不产生重复序号或半行 JSON。
3. 默认配置下说唤醒词不会唤醒或发声；教师点击后可立即对话，且按钮收到明确回执。
4. 教师隐藏/显示儿童端对话窗口后，儿童端状态与教师端回执一致，录制不中断。
