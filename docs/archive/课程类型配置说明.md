# 课程类型配置说明

## 当前状态

目前系统支持根据课程类型配置不同的触发器，但**分析器和比对器是在流水线初始化时全局配置的**，所有课程都使用相同的分析器配置。

## 配置位置

### 1. 全局配置（当前方式）

**配置文件**: `config/analyzers.yaml`

```yaml
analyzers:
  pose:
    enabled: true   # 全局启用/禁用
    mode: real
    sample_rate: 0.01
    
  speech:
    enabled: true   # 全局启用/禁用
    mode: mock

matchers:
  pose:
    enabled: true   # 全局启用/禁用
    threshold: 0.85
    
  speech:
    enabled: true   # 全局启用/禁用
    threshold: 0.80
```

**问题**: 这种方式是全局的，所有课程都会使用相同的配置。

### 2. 课程配置（在启动会话时传递）

**位置**: `app/sockets/handlers.py` - `PlayResourceHandler.handle()`

```python
course_config = {
    'course_type': course_type,  # 'imitation' 或 'naming'
    'enable_realtime': True,
    'enable_window': True,
    'enable_triggers': True,
    'pose_threshold': 0.85,
    'attention_threshold': 0.3
}
analysis_service.start_session(session.session_id, course_config)
```

**当前支持的配置**:
- `course_type`: 课程类型（'imitation', 'naming', 'default'）
- `pose_threshold`: 姿态匹配阈值
- `speech_threshold`: 语音匹配阈值（虽然还没使用）
- `enable_realtime`: 是否启用实时分析
- `enable_window`: 是否启用窗口分析
- `enable_triggers`: 是否启用触发器

**目前不支持**: 动态启用/禁用特定的分析器和比对器

## 解决方案

### 方案1：在流水线处理逻辑中检查（推荐）

在流水线的 `process_realtime()` 方法中，根据 `context.course_type` 决定是否执行分析：

**修改位置**: `app/core/pipelines/vision_pipeline.py`

```python
def process_realtime(self, frame, context):
    # 根据课程类型决定是否执行姿态分析
    if context.course_type in ['imitation', 'pose']:
        # 执行姿态分析和匹配
        pose_result = self._pose_analyzer.analyze_with_sampling(frame, context)
        # ...
    
    # 表情分析（所有课程都可以有）
    if self._face_analyzer:
        face_result = self._face_analyzer.analyze_with_sampling(frame, context)
```

### 方案2：通过 course_config 传递配置（更灵活）

在 `course_config` 中添加分析器启用配置，流水线读取并应用：

**1. 修改 course_config 传递**:

```python
# app/sockets/handlers.py
course_config = {
    'course_type': course_type,
    'enabled_analyzers': {
        'pose': course_type in ['imitation', 'pose'],
        'speech': course_type in ['naming', 'speech'],
        'face': True,  # 所有课程都启用
        'attention': True  # 所有课程都启用
    },
    'enabled_matchers': {
        'pose': course_type in ['imitation', 'pose'],
        'speech': course_type in ['naming', 'speech']
    },
    # ... 其他配置
}
```

**2. 修改流水线读取配置**:

```python
# app/core/pipelines/vision_pipeline.py
def process_realtime(self, frame, context):
    # 从 context 获取课程配置
    course_config = getattr(context, 'course_config', {})
    enabled_analyzers = course_config.get('enabled_analyzers', {})
    enabled_matchers = course_config.get('enabled_matchers', {})
    
    # 姿态分析（根据课程配置）
    if enabled_analyzers.get('pose', True) and self._pose_analyzer:
        pose_result = self._pose_analyzer.analyze_with_sampling(frame, context)
        # ...
        
        # 姿态匹配
        if enabled_matchers.get('pose', True) and self._pose_matcher:
            match_result = self._pose_matcher.match_from_result(pose_result, context)
```

### 方案3：配置文件定义课程类型映射

在 `config/analyzers.yaml` 中定义不同课程类型的配置：

```yaml
# 课程类型配置
course_types:
  imitation:
    enabled_analyzers:
      - pose
      - attention
    enabled_matchers:
      - pose
  
  naming:
    enabled_analyzers:
      - speech
      - attention
    enabled_matchers:
      - speech
  
  default:
    enabled_analyzers:
      - pose
      - speech
      - attention
    enabled_matchers:
      - pose
      - speech
```

## 推荐实现（方案2）

**优点**:
- ✅ 灵活性高，可以在启动会话时动态配置
- ✅ 不需要修改配置文件
- ✅ 支持课程级别的个性化配置

**实现步骤**:

1. 修改 `AnalysisContext` 添加 `course_config` 字段
2. 在 `start_session` 时传递 `course_config` 到 context
3. 在流水线的 `process_realtime` 中根据配置决定是否执行分析

## 当前可用的方式（临时方案）

虽然不能完全禁用分析器的创建，但可以：

1. **在全局配置中启用所有分析器**（保持 `enabled: true`）
2. **在触发器层面控制**（只注册需要的触发器）
3. **在前端过滤结果**（不显示不需要的分析结果）

但这会有性能开销（分析了但不使用）。

## 建议

**短期**: 使用方案1，在流水线处理逻辑中根据 `course_type` 决定是否执行分析

**长期**: 实现方案2，支持完全动态的课程级别配置
