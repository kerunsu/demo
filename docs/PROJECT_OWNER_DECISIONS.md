## D-001 双屏部署拓扑

**状态：已确认**

### 决定

- 机器人主机是一台 Windows 设备，并连接两个显示屏。
- 机器人主机主要承担：
  - 儿童交互屏前端页面呈现；
  - 机器人表情屏前端页面呈现；
  - 麦克风、摄像头等本地设备的数据采集；
  - 机器人语音播放与 GIF 表情动画播放。
- 机器人端本身不承担 VAD、STT、TTS、视觉分析或大模型等高性能计算。
- 两个屏幕分别运行独立的浏览器窗口：
  - 儿童交互屏打开 `/child`；
  - 机器人表情屏打开 `/robot`。
- 后端服务运行在另一台主机上，不运行在机器人双屏主机上。
- 机器人主机通过局域网访问后端服务。
- 后端主机负责：
  - 训练会话与状态编排；
  - 题目、答案和训练流程管理；
  - 领域事件发布；
  - 结构化数据存储；
  - 评估指标聚合；
  - 大模型与报告服务编排；
  - 安全审核流程。
- 当前优先支持“机器人主机 + 独立后端主机”的局域网部署模式，同时保留未来扩展到更多终端的能力。

### 工程影响

- 前端 API 地址和 WebSocket 地址必须通过环境变量或运行时配置提供，禁止继续硬编码为 `127.0.0.1`。
- 后端监听地址必须允许机器人主机通过局域网访问。
- CORS、WebSocket Origin、设备身份和访问控制必须按局域网部署设计。
- 断网、后端不可达、WebSocket 重连和双屏页面刷新都必须有降级与恢复策略。
- 当前开发阶段所有开发和自动化测试暂时在当前本机完成，当前本机视为高性能服务器开发环境。
- 未来迁移到“机器人浏览器终端 -> 局域网 -> 高性能服务器”时，应主要通过配置和部署变化完成，不应重写 Provider 和业务编排。

## D-002 前端组织形式

**状态：已确认**

### 决定

- 第一阶段继续使用同一个 Vite + React 前端工程。
- 在同一工程中提供两个独立运行页面：
  - `/child`：儿童交互页面；
  - `/robot`：机器人表情与语音播放页面。
- 两个页面共享：
  - TypeScript 类型；
  - 领域事件契约；
  - WebSocket 客户端；
  - API 客户端；
  - 运行时配置；
  - 通用错误处理和连接状态组件。
- 两个页面不得依赖彼此的浏览器内存状态进行同步。
- 当前不拆分为两个独立前端仓库；当两个终端未来出现独立发布周期或明显技术差异时再重新评估。

## D-003 状态同步方式

**状态：已确认**

### 决定

- 后端训练会话状态是跨屏交互的唯一事实源。
- HTTP 用于：
  - 创建和查询训练会话；
  - 获取课程和题目数据；
  - 提交答案；
  - 查询报告；
  - 执行不要求即时推送的命令。
- WebSocket 用于：
  - 双屏实时状态同步；
  - 训练领域事件；
  - 动画播放请求与完成回执；
  - 语音链路状态；
  - 客户端连接、断线和恢复。
- 所有跨模块事件至少包含：
  - `eventId`；
  - `eventType`；
  - `sessionId`；
  - `timestamp`；
  - `source`；
  - `correlationId`；
  - `causationId`；
  - `schemaVersion`；
  - `payload`。
- 前端本地状态只用于页面渲染和短期交互，不得作为跨屏训练状态的最终依据。
- 客户端重连后必须能够从后端重新获取会话快照，并处理重复事件。

## D-004 动画运行形式

**状态：已确认资源形态；播放时长与循环属性待逐个验证**

### 已有资源

当前机器人表情动画为 9 个 GIF 文件：

| animationId | 文件名 | 建议语义 |
|---|---|---|
| `eye` | `001_Eye.gif` | 默认待机、自然眼部动作 |
| `curious` | `002_Curious.gif` | 好奇、倾听、等待儿童回应 |
| `happy` | `003_Happy.gif` | 一般答对反馈、温和表扬 |
| `excited` | `004_Excited.gif` | 高强度表扬、课程完成庆祝 |
| `look_down` | `005_LookDown.gif` | 短暂思考或注意转移状态 |
| `sad` | `006_Sad.gif` | 特殊情绪表达；不作为默认答错反馈 |
| `yawn` | `007_Yawn.gif` | 特殊状态或演示用途 |
| `dissatisfied` | `008_Dissatisfied.gif` | 特殊状态；不作为默认儿童答错反馈 |
| `open_eyes` | `009_OpenEyes.gif` | 唤醒、开始训练、恢复关注 |

### 决定

- Codex 不重新制作、修改或重新编码这些 GIF 动画。
- 动画通过机器人表情页面中的统一 `AnimationAdapter` 调用。
- 前端可使用 `<img>` 或等效组件加载 GIF。
- 为保证同一个 GIF 能够从第一帧重新播放，适配器应支持通过更换资源 URL、增加缓存破坏参数或重新创建 DOM 元素的方式重启动画。
- 动画适配层至少提供：
  - `play(animationId, options)`；
  - `stop()`；
  - `showIdle()`；
  - `isPlaying()`；
  - 播放开始事件；
  - 播放完成或预计完成事件；
  - 资源缺失和加载失败事件。
- GIF 本身通常不提供可靠的原生“播放完成”回调，因此：
  - 每个动画需要配置 `expectedDurationMs`；
  - 若 GIF 为循环动画，需要配置 `loop: true`；
  - 非循环动画暂时使用配置时长加计时器产生完成回执；
  - 后续可通过工具读取 GIF 帧信息，校准真实时长。
- 动画在适配器层面可以被新动画替换或中断；不可中断的业务阶段由后端状态机和优先级规则控制。
- 动画资源建议统一放入前端可管理的静态资源目录，例如：
  - `frontend/public/robot-animations/`
  - 或项目后续确认的等效目录。
- 动画清单、资源路径、时长、循环属性和优先级必须集中配置，不得散落硬编码在页面组件中。

### 初始业务映射

- 系统待机：`eye`
- 开始或唤醒：`open_eyes`
- 倾听儿童：`curious`
- 普通答对：`happy`
- 连续答对或课程完成：`excited`
- 思考或等待后端回复：`look_down` 或 `curious`
- 答错：优先使用温和的 `curious`、`eye` 或专门鼓励语音，不默认使用 `sad`、`dissatisfied`
- `sad`、`yawn`、`dissatisfied` 暂不进入默认儿童训练主流程，除非后续由产品负责人明确指定使用场景。

### 待补充验证

在 M3 动画集成前，需要补充：

- 每个 GIF 的实际文件路径；
- 每个 GIF 的实际播放时长；
- 是否循环；
- 图片尺寸和透明背景情况；
- 动画切换时是否需要过渡；
- GIF 是否需要与 TTS 口型或说话状态进一步同步。

## D-005 语音采集与播放位置

**状态：已确认**

### 决定

- 儿童交互屏负责儿童语音采集和录音状态提示。
- 机器人表情屏负责播放机器人的 TTS 语音。
- 后端负责编排：
  - 对话上下文；
  - 回复生成；
  - 儿童安全审核；
  - TTS 任务；
  - 播放指令；
  - 状态机与事件。
- 机器人表情屏在播放语音时同步显示说话、开心、倾听或其他对应动画。
- 浏览器可能限制未经用户操作的自动播放，因此机器人表情屏启动后允许进行一次“启用声音”操作。
- 播放端必须向后端发送：
  - 播放开始；
  - 播放完成；
  - 播放失败；
  - 播放被中断。
- 在没有真实 TTS 时，使用 Mock 音频或预录音验证完整时序。

## D-006 数据存储

**状态：已确认**

### 决定

- 初始正式持久化方案使用 SQLite。
- SQLite 数据库运行在独立后端主机上，而不是机器人双屏主机上。
- 通过 Repository 接口隔离数据访问，未来可迁移到 PostgreSQL 或其他数据库。
- 优先保存：
  - 训练会话；
  - 题目和回答；
  - 领域事件；
  - 响应时间；
  - 提示记录；
  - 注意力与语言表达的结构化观测或聚合特征；
  - 评估指标；
  - 算法与规则版本；
  - 报告；
  - 必要的安全审核结果和审计信息。
- 默认不保存原始视频。
- 默认不长期保存原始音频。
- 是否保存语音转写文本由隐私和业务需求决定；若保存，应支持脱敏、保留期限和删除。
- 数据库需要具备：
  - schema 版本；
  - 迁移机制；
  - 数据保留和删除机制；
  - 备份与恢复方案；
  - 测试数据库隔离。

## D-007 儿童数据外发与本地处理

**状态：最终产品边界已确认；开发阶段测试例外已确认**

### 核心决定

- 未处理的源数据，包括原始音频、原始视频、连续摄像头画面和原始图像，全部禁止发送到外部服务。
- 原始音视频必须在机器人主机或项目控制的本地计算环境中处理。
- 摄像头注意力分析必须本地完成，不得把原始视频帧上传到外部视觉模型。
- STT 的原始音频处理必须本地完成，不得把儿童原始语音上传到外部 STT 服务。

### 开发阶段测试例外

当前事实：当前处于开发阶段，允许使用开发人员录制的测试语音、合成音频、明确授权的非真实儿童测试音频，将上述测试音频发送给云端 STT，并将测试文本发送给云端 TTS，用于比较本地与云端性能、准确率、稳定性和成本。

当前事实：开发阶段仍禁止默认使用真实儿童语音、未经授权上传真实儿童音频、将真实 API Key 写入仓库、在日志中长期保存完整音频或敏感文本。

待确认：最终产品是否允许真实儿童音频上传云端，继续保持为待项目负责人和隐私流程确认的决策。开发阶段允许测试云端服务，不等于最终产品已批准儿童数据上云。

### 可外发的派生数据边界

在经过本地处理后，以下派生数据可以在满足最小必要原则、脱敏和安全检查后发送到已批准的外部大模型服务：

- 去标识化的语音转写文本；
- 当前题目和必要的对话上下文；
- 不包含原始音视频的结构化训练指标；
- 不包含直接身份信息的报告指标；
- 用于生成机器人回复或报告解释的最小必要数据。

发送前必须进行：

1. 本地敏感信息检测；
2. 姓名、学校、住址、联系方式等直接身份信息脱敏；
3. 数据最小化；
4. 供应商白名单检查；
5. 调用目的检查；
6. 日志脱敏；
7. 儿童内容安全策略检查。

### 明确禁止

- 禁止向外部服务发送原始音频文件。
- 禁止向外部服务发送原始视频文件。
- 禁止向外部服务发送连续摄像头画面或原始视频帧。
- 禁止将完整本地训练数据集无差别发送给大模型。
- 禁止在未配置审核和脱敏时启用真实外部 Provider。
- 禁止在代码、日志或文档中记录真实 API Key。

### 当前开发限制

在最终产品真实供应商、授权流程和数据处理协议确认前：

- 使用 Mock STT、Mock LLM、Mock Safety 和 Mock TTS；
- 允许开发本地处理接口和 Provider 抽象；
- 允许开发阶段用授权测试数据接入可关闭的云端 STT/TTS Benchmark；
- 不允许默认上传真实儿童音视频或连续摄像头画面。

## D-008 报告定位

**状态：已确认**

### 决定

- 当前及近期报告定位为：
  - 训练表现分析；
  - 教育辅助参考；
  - 面向教师、治疗师或家长的训练过程总结。
- 当前报告不作为临床诊断、医疗诊断或正式医学评估结论。
- 在真实常模和专业评分标准得到确认前：
  - 不展示虚构的同龄百分位；
  - 不展示无来源的常模结论；
  - 不输出临床诊断式语言；
  - 演示性指标必须明确标注为演示或内部研发数据。
- 核心定量分数由确定性评估引擎、明确规则或经过确认的算法计算。
- 大模型只负责：
  - 解释结构化指标；
  - 生成易读总结；
  - 描述优势和待提升方向；
  - 根据已经确认的规则生成训练建议。
- 大模型不得自由生成核心分数或修改评估引擎结果。
- 大模型生成的报告文案必须经过儿童与专业内容安全审核后才能展示或导出。

## D-010 第一阶段工程目标

**状态：已确认**

### 决定

下一开发阶段只完成以下工程目标：

1. 建立自动化测试基线；
2. 固化共享领域事件、状态机和 Provider 契约；
3. 渐进拆分现有热点文件；
4. 建立儿童屏 `/child` 和机器人表情屏 `/robot` 的页面结构；
5. 完成双屏最小演示闭环；
6. 使用 Mock 动画、Mock STT、Mock LLM、Mock Safety Review 和 Mock TTS；
7. 验证机器人主机连接独立后端主机的局域网架构；
8. 验证答题、动画、语音状态和下一题之间的时序。

### 第一阶段不包含

- 真实外部大模型接入；
- 上传原始音视频的云端服务；
- 正式注意力算法；
- 正式语言能力评分；
- 正式临床或专业评估；
- 完整生产部署；
- 动画资源重新制作。

### 第一阶段完成标准

至少能够稳定演示：

1. 机器人主机打开儿童屏和机器人表情屏；
2. 两个页面连接另一台主机上的后端；
3. 儿童屏开始训练并提交答案；
4. 后端完成判题并发布事件；
5. 机器人表情屏播放对应 GIF 动画；
6. 使用 Mock TTS 或预录音播放反馈；
7. 动画与语音完成后，训练流程进入下一题；
8. 页面刷新或 WebSocket 短暂断开后可以恢复当前会话；
9. 全流程不调用真实外部 API；
10. 自动化测试和构建通过。

## D-012 M4 本地与云端语音 Provider 横向比较

**状态：已确认**

### 决定

- M4 必须横向比较本地和云端 STT/TTS，而不是预设只采用本地方案。
- STT Provider 必须支持 `local`、`cloud`、`mock`。
- TTS Provider 必须支持 `local`、`cloud`、`mock`。
- Provider 接口至少覆盖初始化、健康检查、请求、取消、超时、错误、Provider 标识、模型标识、耗时、是否发生外部网络调用、输入数据是否持久化、降级路径。
- 云端候选只有在环境变量存在时执行；缺少云端 Key 时标记 `CLOUD_CREDENTIALS_PENDING`，不阻塞本地 Benchmark、接口和测试框架。
- 不得把业务逻辑与特定供应商 SDK 直接绑定。

### 工程影响

- M4-002 重新定义为 `本地与云端 STT/TTS 技术 Spike 和横向 Benchmark`。
- Benchmark 需覆盖本地 STT、云端 STT、本地 TTS、云端 TTS，以及本地/云端 STT 与本地/云端 TTS 的端到端组合。
- 测试结果需输出结构化 JSON 和 Markdown 报告。
- 云端测试必须可以通过配置关闭，真实 Key 只从环境变量读取，不进入仓库。
