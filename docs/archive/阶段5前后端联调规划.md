## 八、注意事项

### 性能考虑
1. **视频帧处理频率**
   - 当前配置：30fps
   - Mock分析器处理很快，但真实模型需要考虑节流
   - 建议：分析服务内部已有采样逻辑

2. **WebSocket消息量**
   - 视频帧每秒30个事件
   - 音频块约每秒4-5个事件
   - 分析结果每秒约1-5个事件
   - 建议：观察网络负载，必要时调整

### 错误处理
1. **分析服务异常不应影响录制**
   - 分析失败只记录日志，不中断数据流
   - 录制功能独立运行

2. **前端断连处理**
   - 教师端断连不影响儿童端录制
   - 结果会在队列中缓存

### 调试技巧
1. **后端日志级别**
   - 设置 `DEBUG` 级别查看详细日志
   - 关注 `analysis_service`、`feedback_service` 的日志

2. **浏览器开发者工具**
   - Network 标签查看 WebSocket 消息
   - Console 查看前端日志

### 改动量评估

| 组件 | 改动量 | 说明 |
|------|--------|------|
| app.py | 小 | 添加约20行代码 |
| handlers.py | 中 | 每个Handler添加约10行代码 |

**总结**：改动量不大，主要是"连接"已有的模块。

### 风险点

1. **循环导入问题**
   - 注意services模块之间的导入顺序
   - 建议使用延迟导入

2. **线程安全**
   - 分析服务和反馈服务都使用了锁
   - 但需要注意SocketIO的线程模型

3. **Mock数据的随机性**
   - Mock分析器返回随机数据
   - 可能导致触发器频繁触发
   - 建议调低触发阈值或增加冷却时间
