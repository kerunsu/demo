## 八、关键设计决策

### 1. 会话ID的生成

**选项A**：使用UUID（当前Session模型）
- 优点：唯一性好，不冲突
- 缺点：不直观，难以从ID看出关联

**选项B**：使用组合键 `{studentId}_{courseId}_{itemId}_{timestamp}`
- 优点：直观，易于理解
- 缺点：可能冲突（同一时刻多次播放）

**建议**：使用UUID，但Session模型已包含student_id等信息，可以查询

### 2. 录制开始时机

**选项A**：play_resource时自动开始
- 优点：简单，自动
- 缺点：无法精确控制

**选项B**：单独的start_recording事件
- 优点：精确控制
- 缺点：需要额外事件

**建议**：选项A（play_resource时自动开始），简化流程

### 3. 录制停止时机

**选项A**：下一个play_resource时停止上一个
- 优点：自动切换
- 缺点：可能丢失数据

**选项B**：明确的stop_recording事件
- 优点：精确控制
- 缺点：需要教师端发送

**建议**：选项B（明确的stop_recording事件），更可靠

### 4. 队列大小

**建议**：
- 视频队列：100帧（约3秒@30fps）
- 音频队列：200块（约4秒@50块/秒）

队列满时丢弃最旧的，保证实时性
