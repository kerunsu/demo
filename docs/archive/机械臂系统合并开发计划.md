# 机械臂系统合并开发计划

## 一、当前状态分析

### 主项目 (Flask)
- **技术栈**: Flask + Flask-SocketIO + SQLAlchemy
- **端口**: 8080
- **功能**: 教育训练系统、实时分析、WebSocket 通信

### doll 项目 (Node.js)
- **技术栈**: Express + Socket.io + node-osc
- **端口**: 3000
- **功能**: 机械臂姿态检测、动作录制/播放、课程映射、OSC 硬件通信

### 核心矛盾
两个独立服务端，前端需要同时连接两个 WebSocket，数据不共享，维护成本高。

---

## 二、合并方案选择

### 方案 A：HTTP 代理转发 ❌（当前方案，已否决）
- 优点：改动最小
- 缺点：两个服务、两套 WebSocket、延迟高、维护复杂

### 方案 B：Python 完全重写 ✅（推荐）
- 优点：统一技术栈、单一服务、数据共享、易维护
- 缺点：需要重写约 600 行 Node.js 代码
- 依赖：`python-osc` 库

### 方案 C：子进程管理
- 优点：保留原代码
- 缺点：进程间通信复杂、仍是两套系统

**选择方案 B：Python 完全重写**

### 阶段 3：REST API 路由

#### 3.1 创建 `app/robot/routes.py`（Flask Blueprint）

```python
from flask import Blueprint

robot_bp = Blueprint('robot', __name__, url_prefix='/api/robot')

# 动作管理
GET  /api/robot/motions           # 获取动作列表
GET  /api/robot/motions/<name>    # 获取动作详情
POST /api/robot/motions           # 保存动作
DELETE /api/robot/motions/<name>  # 删除动作
POST /api/robot/play/<name>       # 播放动作
POST /api/robot/stop              # 停止播放

# 映射配置
GET  /api/robot/mapping/full      # 获取完整映射
PUT  /api/robot/mapping/idle      # 设置静态姿势
PUT  /api/robot/mapping/defaults/<auxType>  # 更新通用动作
PUT  /api/robot/mapping/course/<cid>/<auxType>  # 更新课程级
PUT  /api/robot/mapping/student/<sid>/course/<cid>/<auxType>  # 学生-课程级
PUT  /api/robot/mapping/item/<sid>/<cid>/<iid>/<auxType>  # 项目级

# 课程触发（关键接口）
POST /api/robot/course-event      # 外部/内部触发动作

# 基础数据
GET  /api/robot/students          # 学生列表
GET  /api/robot/courses           # 课程列表
```

#### 3.2 在 `app.py` 注册 Blueprint
```python
from app.robot.routes import robot_bp
app.register_blueprint(robot_bp)
```

### 阶段 4：WebSocket 事件集成

| `play_motion` | 前端→后端 | 播放指定动作 |
| `stop_playback` | 前端→后端 | 停止播放 |
| `recording_status` | 后端→前端 | 录制状态反馈 |
| `playback_status` | 后端→前端 | 播放状态反馈 |

### 阶段 6：集成与测试

#### 6.1 内部集成点

**play_resource 事件处理流程（修改后）**：
```
教师端点击播放
    ↓
play_resource 事件
    ↓
    ├─→ PlayResourceHandler.handle() (创建会话、启动分析)
    │
    ├─→ robot_service.trigger_course_event(data)  ← 直接调用
    │   └─ MappingResolver.findMotions()
    │   └─ MotionPlayer.play()
    │   └─ OSC → 硬件
    │
    └─→ emit('play_resource') 转发给儿童端
```

## 八、风险与注意事项

1. **OSC 通信**：`python-osc` 与 `node-osc` API 略有不同，需适配
2. **线程安全**：MotionPlayer 播放使用后台线程，需注意同步
3. **前端依赖**：TensorFlow.js 姿态检测逻辑无需改动（纯前端）
4. **数据兼容**：`doll/data/*.json` 格式保持不变
5. **Socket.io 兼容**：Flask-SocketIO 与原 Socket.io 事件格式一致
