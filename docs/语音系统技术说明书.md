## 1. 系统概述

### 1.1 设计目标与功能定位

语音系统是特殊儿童教育训练系统的**儿童端语音播放子系统**，主要解决以下需求：

| 需求 | 说明 |
|------|------|
| **语音多样性** | 同一语义（如"表扬"）有多个不同录音，避免单调重复 |
| **智能选择** | 支持随机、顺序、加权等多种选择策略，避免短时间内重复 |
| **课程关联** | 不同课程类型（命名、模仿、拟声等）可配置不同的默认语音 |
| **实时通信** | 教师端操作后，儿童端即时播放对应语音 |
| **状态反馈** | 儿童端播放状态实时回传给教师端 |

### 1.2 核心特性一览

```
✅ YAML配置驱动      - 所有语音条目通过 YAML 文件配置，无需改代码
✅ 多选择策略        - 随机/顺序/加权/上下文感知 四种策略
✅ 冷却机制          - 防止同一语音短时间内重复播放
✅ 播放队列          - 支持连续播放、优先级排序、中断控制
✅ 预加载            - 提前加载音频文件，减少播放延迟
✅ 房间隔离          - 基于 Socket.IO Room 的消息精准投递
```

### 1.3 技术栈概览

| 层级 | 技术 | 说明 |
|------|------|------|
| 后端框架 | Flask + Flask-SocketIO | Web框架 + WebSocket支持 |
| 配置格式 | YAML | 语音清单配置 |
| 通信协议 | Socket.IO | 双向实时通信 |
| 前端播放 | HTML5 Audio API | 浏览器原生音频播放 |
| 文件格式 | MP3 | 音频文件格式 |

### 2.2 模块职责划分

语音系统由 **6个后端模块** + **1个前端模块** 组成：

| 模块 | 文件 | 职责 |
|------|------|------|
| **数据模型** | `app/audio/models.py` | 定义数据结构（AudioEntry, AudioFile, AudioContext等） |
| **注册表** | `app/audio/registry.py` | 加载YAML配置，提供语音条目查询接口 |
| **选择器** | `app/audio/selector.py` | 根据策略选择具体的音频文件 |
| **事件发送器** | `app/audio/events.py` | 通过Socket.IO发送播放事件到客户端 |
| **播放控制器** | `app/audio/controller.py` | 管理播放状态，处理停止命令 |
| **语音服务** | `app/audio/service.py` | 业务逻辑入口，处理play_resource中的语音触发 |
| **前端播放器** | `static/js/audio_player.js` | 接收播放事件，管理播放队列，实际播放音频 |

### 2.3 模块间依赖关系

```
                    ┌─────────────┐
                    │   models    │  ← 纯数据结构，无依赖
                    └──────┬──────┘
                           │
                    ┌──────▼──────┐
                    │  registry   │  ← 依赖 models，加载YAML
                    └──────┬──────┘
                           │
                    ┌──────▼──────┐
                    │  selector   │  ← 依赖 registry + models
                    └──────┬──────┘
                           │
              ┌────────────┼────────────┐
              │            │            │
       ┌──────▼──────┐  ┌──▼───┐  ┌─────▼─────┐
       │   events    │  │      │  │controller │
       │  (emitter)  │  │      │  │           │
       └──────┬──────┘  │      │  └───────────┘
              │         │      │
              └────┬────┘      │
                   │           │
            ┌──────▼──────┐    │
            │   service   │◀───┘  ← 业务入口，协调各模块
            └─────────────┘
```

**依赖规则**：
- `models` 是最底层，不依赖任何其他模块
- `registry` 依赖 `models`，负责数据加载
- `selector` 依赖 `registry`，负责选择逻辑
- `events` 和 `controller` 依赖 `selector`，负责对外通信
- `service` 是顶层入口，协调所有模块

### 3.3 房间机制（Room）与消息路由

语音系统使用 Socket.IO 的 **Room 机制** 实现消息精准投递：

```
┌─────────────────────────────────────────────────────────────────┐
│                        Socket.IO 房间结构                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  会话 session_abc123 创建后：                                    │
│                                                                 │
│  ┌─────────────────────────┐   ┌─────────────────────────┐     │
│  │ session_abc123_teacher  │   │  session_abc123_child   │     │
│  │                         │   │                         │     │
│  │  - 教师端浏览器加入      │   │  - 儿童端浏览器加入      │     │
│  │  - 接收分析结果          │   │  - 接收语音播放事件      │     │
│  │  - 接收状态更新          │   │  - 接收停止播放命令      │     │
│  │                         │   │                         │     │
│  └─────────────────────────┘   └─────────────────────────┘     │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**房间加入流程**：

1. **儿童端**收到 `play_resource` 事件时，发送 `join_session`：
   ```javascript
   socket.emit('join_session', {
     sessionId: 'abc123',
     role: 'child'
   });
   ```

2. **服务器**将客户端加入对应房间：
   ```python
   # app/sockets/events.py
   room = f"session_{session_id}_child"
   join_room(room)
   ```

3. **语音事件**只发送到儿童端房间：
   ```python
   # app/audio/events.py
   self.socketio.emit('play_audio', event_data, room='session_abc123_child')
   ```

**为什么需要房间机制？**

| 场景 | 不用房间 | 使用房间 |
|------|----------|----------|
| 多个教师同时上课 | 所有儿童端都收到所有语音 ❌ | 每个儿童只收到自己课程的语音 ✅ |
| 教师端误收语音 | 教师端也会播放语音 ❌ | 语音只发给儿童端房间 ✅ |
| 定向停止播放 | 无法只停止特定儿童 ❌ | 可精准控制每个会话 ✅ |

## 4. 核心模块详解

### 4.1 数据模型层（models.py）

**文件位置**: `app/audio/models.py`

数据模型层定义了语音系统的所有数据结构，是其他模块的基础。

#### 4.1.1 核心类一览

| 类名 | 用途 | 关键字段 |
|------|------|----------|
| `SelectionStrategy` | 选择策略枚举 | RANDOM, SEQUENTIAL, WEIGHTED, CONTEXT_AWARE |
| `AudioStatus` | 播放状态枚举 | IDLE, PLAYING, STOPPED, ENDED, ERROR |
| `AudioFile` | 单个音频文件 | path, weight, description |
| `AudioEntry` | 语音条目（对应YAML中一个entry） | entry_id, category, files, selection, cooldown |
| `AudioContext` | 播放上下文 | session_id, student_id, course_type |
| `PlaybackStatus` | 播放状态记录 | session_id, status, current_audio_id |
| `AudioManifest` | 整个YAML清单 | entries, aliases, course_defaults |

#### 4.1.2 AudioEntry 详解

`AudioEntry` 是最核心的数据结构，对应 YAML 中的一个语音条目：

```python
@dataclass
class AudioEntry:
    entry_id: str                       # 条目ID，如 "greeting_hello"
    category: str                       # 分类，如 "system.greeting"
    intent: str                         # 语义意图，如 "hello"
    description: str                    # 描述
    files: List[AudioFile]              # 音频文件列表
    selection: SelectionStrategy        # 选择策略（默认RANDOM）
    cooldown: int                       # 冷却次数（避免重复）
    tags: List[str]                     # 标签
    
    # 拟声课程专用
    question_files: List[AudioFile]     # 提问语音
    answer_files: List[AudioFile]       # 回答语音
```

**与 YAML 的对应关系**：

```yaml
# YAML 配置
praise_correct:                    # → entry_id
  category: feedback.praise        # → category
  intent: correct                  # → intent
  description: "表扬 - 正确"       # → description
  files:                           # → files
    - path: "301/001/001.mp3"
    - path: "301/001/002.mp3"
  selection: random                # → selection
  cooldown: 2                      # → cooldown
```

#### 4.1.3 AudioContext 用法

`AudioContext` 用于传递上下文信息，支持上下文感知选择：

```python
context = AudioContext(
    session_id='abc123',
    student_id=1,
    course_type='naming',
    course_id=5,
    item_id=12
)

# 传递给选择器
file_path = selector.select('praise_correct', context)
```

### 4.2 注册表（registry.py）

**文件位置**: `app/audio/registry.py`

注册表负责加载 YAML 配置文件，并提供语音条目的查询接口。

#### 4.2.1 初始化与加载

```python
# 获取单例实例（自动加载 config/audio_manifest.yaml）
registry = get_audio_registry()

# 手动指定配置文件
registry = AudioRegistry()
registry.load_manifest('config/custom_manifest.yaml')
```

#### 4.2.2 查询接口

| 方法 | 用途 | 示例 |
|------|------|------|
| `get_entry(entry_id)` | 根据ID获取条目（支持别名） | `registry.get_entry('praise')` |
| `get_by_category(category)` | 根据分类获取条目列表 | `registry.get_by_category('system.greeting')` |
| `get_by_intent(intent)` | 根据语义意图获取 | `registry.get_by_intent('hello')` |
| `get_by_tags(tags)` | 根据标签获取 | `registry.get_by_tags(['animal', 'cat'])` |
| `get_course_default(course_type, audio_type)` | 获取课程默认语音ID | `registry.get_course_default('naming', 'praise')` |
| `resolve_alias(alias)` | 解析别名 | `registry.resolve_alias('praise')` → `'praise_correct'` |

#### 4.2.3 别名解析机制

注册表支持别名，方便使用简短名称：

```yaml
# YAML 中定义别名
aliases:
  praise: praise_correct
  question: attention_whats_this
```

```python
# 使用别名查询（自动解析）
entry = registry.get_entry('praise')  # 实际返回 praise_correct 条目
```

### 4.3 选择器（selector.py）

**文件位置**: `app/audio/selector.py`

选择器根据配置的策略，从多个音频文件中选择一个进行播放。

#### 4.3.1 四种选择策略

| 策略 | YAML值 | 说明 |
|------|--------|------|
| **随机选择** | `random` | 随机选择，支持冷却机制避免重复 |
| **顺序播放** | `sequential` | 按顺序循环播放 |
| **加权选择** | `weighted` | 根据文件的 weight 属性加权随机 |
| **上下文感知** | `context` | 根据学生、课程等上下文智能选择（预留） |

#### 4.3.2 冷却机制详解

冷却机制防止同一语音短时间内重复播放：

```yaml
praise_correct:
  files:
    - path: "301/001/001.mp3"   # 索引0
    - path: "301/001/002.mp3"   # 索引1
    - path: "301/001/003.mp3"   # 索引2
    - path: "301/001/004.mp3"   # 索引3
  selection: random
  cooldown: 2                   # 最近2次播放的文件不会被选中
```

**工作原理**：

```
播放历史: [0, 2, 1]  （最近播放了索引0、2、1的文件）
cooldown: 2          （排除最近2个）
排除集合: {2, 1}     （索引2和1被排除）
可选范围: [0, 3]     （只能从索引0或3中选择）
```

#### 4.3.3 主要方法

```python
selector = get_audio_selector()

# 基础选择
file_path = selector.select('praise_correct')
# 返回: 'resources/audios/301/001/003.mp3'

# 为课程选择（便捷接口）

    course_type='naming',
    audio_type='praise'
)

# 为拟声课程选择

    animal_name='cat',
    is_question=True  # True=提问语音, False=回答语音
)

# 重置播放历史

selector.reset_history()                   # 重置所有
```

## 6. 前端播放器

### 6.1 AudioPlayer 类设计

**文件位置**: `static/js/audio_player.js`

AudioPlayer 是儿童端的音频播放器，负责接收服务器的播放事件并管理音频播放。

#### 6.1.1 类结构

```javascript
class AudioPlayer {
    constructor(socket, sessionId) {
        this.socket = socket;           // Socket.IO 实例
        this.sessionId = sessionId;     // 会话ID
        
        // 播放状态
        this.currentAudio = null;       // 当前 Audio 对象
        this.currentEntryId = null;     // 当前语音条目ID
        this.currentFilePath = null;    // 当前文件路径
        this.playQueue = [];            // 播放队列
        this.isPlaying = false;         // 是否正在播放
        this.isStopped = false;         // 是否被停止
        
        // 预加载缓存
        this.preloadedAudios = new Map();
        this.maxPreloadSize = 10;
        
        this._registerSocketEvents();
    }
}
```

#### 6.1.2 初始化时机

AudioPlayer 在儿童端收到第一个 `play_resource` 事件时初始化：

```javascript
// child.js 中的初始化逻辑
socket.on("play_resource", (payload) => {
    if (sessionId) {
        // 加入会话房间
        socket.emit('join_session', {
            sessionId: sessionId,
            role: 'child'
        });
        
        // 初始化音频播放器
        if (!audioPlayer && window.AudioPlayer) {
            audioPlayer = new window.AudioPlayer(socket, sessionId);
        }
    }
});
```

#### 6.1.3 事件监听

AudioPlayer 监听两个 Socket.IO 事件：

| 事件 | 触发时机 | 处理逻辑 |
|------|----------|----------|
| `play_audio` | 服务器要求播放语音 | 加入队列并开始播放 |
| `stop_audio` | 服务器要求停止播放 | 停止当前播放，可选清空队列 |

```javascript
_registerSocketEvents() {
    this.socket.on('play_audio', (data) => {
        this._handlePlayAudio(data);
    });
    
    this.socket.on('stop_audio', (data) => {
        this._handleStopAudio(data);
    });
}
```

---

### 6.2 播放队列与优先级

#### 6.2.1 队列机制

AudioPlayer 使用队列管理多个播放请求：

```
收到 play_audio 事件
    │
    ▼
加入播放队列 playQueue
    │
    ▼
按优先级排序（priority 大的在前）
    │
    ▼
如果当前没有播放 → 开始播放队列第一个
如果正在播放 → 等待当前播放完成后自动播放下一个
```

#### 6.2.2 优先级排序

```javascript
// 加入队列
this.playQueue.push({
    entryId: entry_id,
    filePath: file_path,
    priority: priority,
    interrupt: interrupt
});

// 按优先级降序排序
this.playQueue.sort((a, b) => b.priority - a.priority);
```

**优先级示例**：

| 场景 | priority | 效果 |
|------|----------|------|
| 普通语音 | 0 | 按顺序播放 |
| 重要提示 | 1 | 插队到普通语音之前 |
| 紧急中断 | 2 + interrupt:true | 立即中断当前播放 |

#### 6.2.3 中断机制

当收到 `interrupt: true` 的播放请求时：

```javascript
if (interrupt && this.isPlaying) {
    this._stopCurrentAudio();  // 停止当前播放
    this.playQueue = [];       // 清空队列
}
// 然后加入新的播放请求
```

### 6.3 预加载机制

#### 6.3.1 预加载原理

预加载可以提前下载音频文件，减少播放时的延迟：

```javascript
preloadAudio(filePath) {
    // 检查是否已预加载
    if (this.preloadedAudios.has(filePath)) {
        return;
    }
    
    // 缓存已满时移除最早的
    if (this.preloadedAudios.size >= this.maxPreloadSize) {
        const firstKey = this.preloadedAudios.keys().next().value;
        this.preloadedAudios.delete(firstKey);
    }
    
    // 创建并预加载
    const audio = new Audio(`/static/${filePath}`);
    audio.preload = 'auto';
    this.preloadedAudios.set(filePath, audio);
}
```

#### 6.3.2 使用预加载的音频

播放时优先使用预加载的 Audio 对象：

```javascript
_playAudio(entryId, filePath) {
    // 检查是否已预加载
    let audio = this.preloadedAudios.get(filePath);
    
    if (!audio) {
        // 未预加载，创建新的
        audio = new Audio(`/static/${filePath}`);
    } else {
        // 使用预加载的，从缓存移除
        this.preloadedAudios.delete(filePath);
    }
    
    this.currentAudio = audio;
    audio.play();
}
```

#### 6.3.3 预加载策略建议

| 场景 | 建议 |
|------|------|
| 常用表扬语音 | 课程开始时预加载 |
| 课程特定语音 | 切换课程项时预加载下一个 |
| 系统语音 | 页面加载时预加载问候语 |

### 6.4 状态回调

#### 6.4.1 状态类型

AudioPlayer 向服务器报告以下状态：

| 状态 | 触发时机 | 说明 |
|------|----------|------|
| `playing` | audio.onplay | 开始播放 |
| `stopped` | 被停止命令中断 | 主动停止 |
| `finished` | audio.onended | 正常播放完成 |
| `error` | audio.onerror | 播放出错 |

#### 6.4.2 状态数据格式

```javascript
_sendStatus(status, currentTime, duration, errorMessage = '') {
    const statusData = {
        session_id: this.sessionId,
        status: status,                    // 'playing' | 'stopped' | 'finished' | 'error'
        entry_id: this.currentEntryId,     // 语音条目ID
        file_path: this.currentFilePath,   // 文件路径
        current_time: currentTime,         // 当前播放时间（秒）
        duration: duration                 // 总时长（秒）
    };
    
    if (errorMessage) {
        statusData.error_message = errorMessage;
    }
    
    this.socket.emit('audio_status', statusData);
}
```

#### 6.4.3 服务器端处理

服务器通过 `AudioController.on_audio_status()` 处理状态回调：

```python
# app/sockets/audio_events.py
@socketio.on('audio_status')
def handle_audio_status(data):
    controller = get_audio_controller()
    if controller:
        session_id = data.get('session_id')
        controller.on_audio_status(session_id, data)
```

# app/audio/service.py
def process_play_resource(self, session_id: str, data: Dict[str, Any]) -> bool:
    aux = data.get('aux', {})
    
    if aux.get('question'):
        # ...
    elif aux.get('praise'):

### 8.2 常见问题与解决方案

#### 问题1：点击按钮后儿童端没有声音

**排查步骤**：

```
步骤1: 检查后端日志
─────────────────────────────────────────────────────────
查找: "[AudioService] 触发表扬语音" 或 "[AudioService] 触发问题语音"

✅ 有此日志 → 后端已处理，继续步骤2
❌ 没有此日志 → 检查 aux 参数是否正确传递

步骤2: 检查语音选择
─────────────────────────────────────────────────────────
查找: "发送课程语音: room=session_xxx_child"

✅ 有此日志 → 事件已发送，继续步骤3
❌ 没有此日志 → 检查 YAML 中 course_defaults 配置

步骤3: 检查儿童端是否在房间中
─────────────────────────────────────────────────────────
查找: "joined_session确认" (儿童端控制台)

✅ 有此日志 → 已加入房间，继续步骤4
❌ 没有此日志 → 检查 join_session 是否发送

步骤4: 检查前端是否收到事件
─────────────────────────────────────────────────────────
查找: "[AudioPlayer] 收到 play_audio 事件" (儿童端控制台)

✅ 有此日志 → 继续步骤5
❌ 没有此日志 → 房间名不匹配或 Socket 连接问题

步骤5: 检查音频文件
─────────────────────────────────────────────────────────
查找: "[AudioPlayer] 播放错误" 或 网络请求 404

✅ 无错误 → 检查浏览器音频权限
❌ 有 404 → 音频文件路径错误或文件不存在
```

**常见原因与解决**：

| 原因 | 解决方案 |
|------|----------|
| 儿童端未加入房间 | 确保 `join_session` 在 `play_resource` 之后发送 |
| 课程类型不匹配 | 检查 YAML 中 `course_defaults` 是否包含该课程类型 |
| 音频文件不存在 | 检查 `static/resources/audios/` 下文件是否存在 |
| 浏览器自动播放策略 | 需要用户先与页面交互（点击）才能播放音频 |

---

#### 问题2：语音总是播放同一个文件

**可能原因**：

1. **条目只有一个文件**
   ```yaml
   # 检查 YAML 中文件数量
   praise_correct:
     files:
       - path: "301/001/001.mp3"   # 只有一个文件
   ```

2. **冷却设置过高**
   ```yaml
   praise_correct:
     files: [...]  # 假设有5个文件
     cooldown: 5   # 冷却=文件数，永远只能选最新的
   ```
   **解决**：`cooldown` 应小于文件数量

3. **选择策略为顺序但文件少**
   ```yaml
   selection: sequential  # 顺序播放
   files:
     - path: "001.mp3"    # 只有一个，永远播放这个
   ```

---

#### 问题3：YAML 加载失败

**错误日志**：
```
[audio.registry] 解析 YAML 配置失败: ...
```

**常见原因**：

| 错误类型 | 原因 | 解决方案 |
|----------|------|----------|
| `ScannerError` | 缩进错误 | 使用空格缩进，不要用Tab |
| `ParserError` | 语法错误 | 检查冒号、引号是否匹配 |
| `KeyError` | 缺少必填字段 | 确保 category, intent, description, files 都有 |

**验证 YAML 语法**：

```python
# 快速验证脚本
import yaml
with open('config/audio_manifest.yaml', 'r', encoding='utf-8') as f:
    data = yaml.safe_load(f)
    print(f"加载成功，共 {len(data.get('entries', {}))} 个条目")
```

---

#### 问题4：音频文件 404 错误

**前端控制台**：
```
GET http://127.0.0.1:8080/static/resources/audios/xxx/001.mp3 404 (Not Found)
```

**排查**：

1. **检查文件是否存在**
   ```powershell
   Test-Path "static\resources\audios\xxx\001.mp3"
   ```

2. **检查路径拼写**
   - YAML 中路径区分大小写
   - 目录名和文件名必须完全匹配

3. **检查 base_path 配置**
   ```yaml
   base_path: "resources/audios"  # 不要有 static/ 前缀
   ```

---

#### 问题5：aux 操作没有触发语音

**症状**：第一次播放有声音，点击表扬/提问按钮没有声音

**原因**：aux 操作分支没有调用语音服务

**检查位置**：`app/sockets/handlers.py` 中 `PlayResourceHandler.handle()`

```python
# 确保 aux 操作分支有以下代码
if is_aux_operation and existing_session:
    # 处理语音播放（这段代码必须存在）
    from app.audio import get_audio_service
    audio_service = get_audio_service()
    audio_service.process_play_resource(
        existing_session.session_id, 
        audio_data
    )
```
