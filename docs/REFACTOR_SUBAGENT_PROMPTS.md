# 六块模块化重构：五阶段子智能体执行提示词

本文包含五个必须按顺序执行的提示词。每个阶段都采用“先冻结行为、再加接口、再迁移实现、最后验证”的方式；后一个子智能体必须先阅读前一阶段的交付物和测试结果，不得跳阶段。这里的“保持不变”包括页面呈现与操作顺序、HTTP 路径/方法/状态码/JSON、Socket.IO 事件名/方向/payload/room/时序、会话隔离与幂等语义、原子交互、录制启停和补传、数据库已有数据、已有资源选择结果、报告和评分、机器人动作/表情/语音效果、启动方式及发布包。任何无法证明等价的改动都不得合入。获准新增的产品能力只有四类：①任何持久采集开始前，当前部署方案中启用且标记为 required 的设备和模块必须全部自检 success，采用“预检/预留（不落盘）→原子开录→首帧/首音频块确认”的两阶段门禁；②环境摄像头和环境麦克风支持零到多台，并可由控制端增删、启停、设角色和 required/optional；③多模态 session、轨道、文件完整性、存储健康和时间同步状态可在控制端查看与管理；④控制端支持动作/表情素材批量导入，并增加“课程→交互事件/提问情境→台词→动作、表情、固定语音或 TTS 及时序”的新绑定模型。新能力必须通过新增接口或兼容扩展实现，原接口与旧 course_map 行为继续可用。

## 全阶段统一执行门禁

四项核心结果按顺序为：已有功能与数据安全；稳定、模块化和易维护；控制端可自由编排表情/动作/固定语音或 TTS 及其时序；多模态数据稳定落盘并在控制端可控、可视、可追溯。性能优化不得排在兼容性之前。每个子智能体开始前必须阅读根 `AGENT.md`，它与本文件冲突时采用更严格的兼容和安全要求。

每阶段只能在上一阶段的测试、契约快照、回退演练和交付文档通过后开始；若基线存在既有失败，先记录、复现和隔离，不能把新增失败归为基线。每次只迁移一个可独立验证的切片，旧实现通过适配器或 feature flag 保留，禁止多个子智能体并行修改同一核心文件、契约或数据 schema。未完成真机验证的能力只能标记为“待真机验收”，不能宣称完成。

统一降级矩阵必须被实现并自动测试：InteractionProfileV2、素材解析或新控制页面失败时回退旧 course_map、旧素材、旧接口和旧页面入口；新分析模型失败时优先回退原模型，无原模型的 optional 能力输出明确 degraded/no-data，required 能力按既有门禁阻止开始；optional 环境轨失败可跳过并记录，required 轨失败必须阻止正式采集；新索引、manifest 扩展或可视化失败不得中断既有 session 主文件落盘，无法保证主媒体安全时必须在正式开录前失败。任何降级都要在日志、session 元数据和控制端显示原因、版本、时间、影响范围与当前实际执行路径，禁止静默降级或返回半套动作/表情/语音。

控制端除设备管理和交互编排外，还必须提供多模态 session 可视化：展示 session 状态、设备与 `trackId`、主/环境文件、轨道开始结束与缺口、首帧/首块确认、容量/写入健康、质量指标、相对统一时间轴的偏移、丢帧/丢块及降级原因；支持按权限执行预览、测试、启停配置和导出/下载，但不得从前端直接访问任意服务器路径或绕过存储服务。所有新增删除能力必须有引用保护、确认、审计和可恢复策略。

## 提示词二：建立六块骨架、稳定接口与薄门面

```text
你是第二阶段负责人。先阅读第一阶段 docs/refactor 全部交付物、契约快照和测试基线；若缺失、过时或基线失败，先补齐，不得直接搬目录。目标是在不改变任何运行行为的前提下建立六块清晰骨架和依赖规则，并优先把 app.py 与 app/sockets/events.py 变成可逐步抽离的“门面”，不是一次性重写。建议目标归属可采用现有技术栈内的目录：前端继续保留 teacher_frontend、templates、static；后端新增或收敛 app/facade（bootstrap/application_factory、routes、sockets、presenters）；采集收敛到 app/acquisition；存储保留并扩展 app/storage（含 repositories/content_catalog）；计算收敛到 app/computation；语音对话保留 app/dialogue；app/contracts 仅放无框架依赖的 DTO/Protocol/事件信封。目录名可根据第一阶段结论微调，但六块语义和依赖方向不能模糊。不要换 Flask、Socket.IO、React/Vite、SQLAlchemy/SQLite，不拆微服务，不引入消息中间件或大型 DI 框架；使用构造参数、轻量容器/工厂和 adapter 即可。

先定义稳定端口而非移动实现：SessionRepository/RecordingRepository/ContentCatalog、DeviceRegistry/DeviceDiscoveryPort/DeviceBroker、CapturePort/CaptureSink、AssetLibrary/BatchImportService、InteractionProfileRepository/BehaviorResolver、AnalysisEngine/ModelProvider、CourseProgression/DecisionEngine、DialoguePort/SpeechOutput、RobotCommandPort/EventPublisher/Clock 等 Protocol 或抽象接口；DTO 必须是纯数据，明确字段、可选值、单位、时间基准、版本和错误语义。设备 DTO 必须支持跨 Server/Runtime 的 0..N 摄像头/麦克风和稳定 deviceId/trackId；素材 DTO 必须把逻辑 assetId/version 与物理文件名分离；交互 DTO 必须显式携带 course/event/scene/line 上下文。对外 JSON/Socket 字段继续由 facade presenter/adapter 生成，内部可以规范命名但不得迫使旧前端改契约；新增控制端能力使用新版本化 endpoint 或兼容可选字段。建立单一 composition root，集中创建 Flask/SocketIO、数据库、服务、线程、队列、Robot Runtime client、voice service 和回调连接；导入模块不能自动启动线程、打开摄像头/麦克风、创建文件或修改数据库。保留 python app.py、现有 URL、Blueprint 前缀、Socket 注册函数和 app 包历史导入路径；旧模块暂时改为兼容 shim/委托，新代码调用稳定接口，严禁循环导入和 facade 被领域模块反向 import。

把 app.py 的页面/API 分组迁入 Blueprint 时，每次只迁一个同类路由并运行契约测试；route 函数只允许做 request 解析、权限/格式校验、调用 application use case、将结果映射为完全相同的 response。把 app/sockets/events.py 按连接与 presence、训练生命周期、资源播放、采集上行、互动课、评分、机器人桥分成注册器/adapter，但事件名、注册次数、room、broadcast/to/include_self、ack 顺序、异常回包和日志相关 ID 必须保持一致。play_resource、prepare/finalize/cancel 和 robot/audio 的原子互斥与幂等缓存属于应用用例/计算协调，不应散落在 Socket 装饰器里；迁移时先包裹现有函数，再抽取状态对象，不要重新发明状态机。任何共享可变字典都要有明确所有者、锁和生命周期；线程停止必须可重复调用，测试 teardown 不得泄漏后台线程。

增加架构守卫测试：前端代码不得读取 DB/服务端路径；storage 不得 import facade、SocketIO、Flask request 或具体硬件；acquisition 不得 import LLM/报告评分或决定落盘文件名；computation 不得 import Flask/SocketIO、cv2 VideoCapture/PyAudio 文件写入实现或 dialogue service；dialogue 不得直接操作 DB/录制器/机器人实现，只能产出稳定播报/交互命令；facade 可以依赖各块公开端口但不得包含业务公式。可用 AST/import-linter 风格的自建轻量测试，避免新增沉重工具。每个迁移提交都要运行相关测试和 python -m pytest tests -q，并至少完成一次 Flask 测试客户端与 Socket 测试客户端的黄金链路。交付 docs/refactor/10-target-layout.md、11-public-interfaces.md、12-composition-root.md、13-migration-log.md；验收标准是新骨架与接口真实被至少一条完整链路使用，旧入口/旧 import 全部兼容，HTTP/Socket 快照无差异，UI 无变化，所有既有测试通过。不能为了“代码漂亮”同时移动六块；发现行为差异立即回滚该小步并补 characterization test。
```

## 提示词三：采集、存储与统一时间轴重构

为交互方案建立版本化 InteractionPlan/ResourceResolver：课程内容、问题、提示、表扬、动作、表情、固定语音/TTS、触发条件和时序偏移由稳定 ID 引用，底层继续读取现有 CSV/YAML/静态媒体/动作映射和 dialogue phrases，旧配置未迁移时结果不变。一次交互编排应生成同一个 behaviorId/requestId 下的原子命令包，例如 VisualCommand、SpeechCommand、MotionCommand、ExpressionCommand、CourseCommand；由现有全局 behavior mutex/机器人服务完成 reserve→prepare→commit/abort，任何一项 busy/失败时不得出现旧画面提前消失、音频泄漏、动作/表情半执行或 watchdog 提前启动。配置采用 draft→validate→preview→publish→rollback，已发布版本不可原地修改；配置快照绑定训练/行为版本，运行中的训练不因管理员编辑配置而中途改变。课程推进只发布领域事件/命令，不直接 emit Socket；facade adapter 保持原事件 payload 和发送顺序。

语音对话定义 DialogueRequest（session/course/question/page context/audio or text/history fingerprint）与 DialogueResponse（text、lineId、eventKey/sceneKey、SpeechCommand、可选安全/降级原因），ASR/LLM/TTS provider 均可替换且有 timeout/cancel/health；保留当前 voice-service 自动拉起与 FunASR/外部环境配置，禁止把密钥、模型路径写死。对话生成或规则话术在进入动作/表情解析前必须携带稳定 lineId、course 与 event context；自由生成文本无法预先绑定时使用明确的 event/scene fallback，禁止靠模糊中文关键词偷偷匹配动作。对话历史必须按儿童/session/课程/题目隔离，在 course type/question fingerprint 变化时保持现有清理规则；重连、重复音频、TTS 回声、唤醒误触发、危险或离题问题的规则回复都要有测试。完成后拆小 analysis_service、trigger/actions、dialogue service/sockets 和 robot interaction 的职责，但保留旧公开类/函数 adapter。测试覆盖原有 attention/report/teacher rating、trigger session isolation、interactive atomic behavior、busy audio、dialogue page context、speak emit、browser TTS、robot stability，并增加模型插件 contract、配置快照、决策确定性、对话 provider 超时、原子多模态命令、16 个首批事件、各课程 question 分流、scene/line 精确命中、V2→legacy fallback、resolutionTrace、草稿发布回滚、训练中版本冻结，以及动作/表情 0/1/N 文件批量导入、部分坏包、重复名、ZIP 路径穿越、引用保护和事务回滚测试。交付 docs/refactor/30-computation.md、31-model-plugin-guide.md、32-dialogue-boundary.md、33-interaction-plan-schema.md、34-event-catalog.md、35-asset-library-and-batch-import.md、legacy 映射迁移报告和一个最小“新增假模型/新增课程事件/新增交互方案”示例。验收标准是新模型、新事件、新课程情境、新台词和新动作/表情素材无需修改其他五块即可接入；计算与对话无反向依赖；未发布 V2 配置的课程继续得到与旧系统一致的动作、表情、话术和时序；性能指标至少不退化并有测量证据。
