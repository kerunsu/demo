# 目标产品需求 V2

本文定义未来双屏机器人产品目标。标记含义：`已确认` 来自用户目标或当前代码事实；`当前推测` 是基于架构可行性的建议；`待确认` 需要项目负责人决策。

## 1. 产品目标

| 状态 | 需求 |
| -- | -- |
| 已确认 | 当前完成的是本机 Web Demo，未来目标是双屏机器人训练系统。 |
| 已确认 | 儿童点击或语音答题后，儿童屏、机器人表情动画和语音反馈需要联动。 |
| 已确认 | 定量评分由明确规则或算法计算，LLM 主要生成解释性文字。 |
| 待确认 | 产品是否面向正式教学、公开演示、家庭使用或专业机构使用。 |

## 2. 用户与终端

| 状态 | 需求 |
| -- | -- |
| 已确认 | 主要用户是儿童；演示者、老师或家长是辅助使用者。 |
| 已确认 | 未来至少包含儿童交互屏和机器人表情屏两个独立运行页面。 |
| 当前推测 | 后端应作为两个屏幕的会话事实源，屏幕通过事件订阅保持一致。 |
| 待确认 | 两个屏幕是否同机、局域网多机、机器人内置屏或独立硬件。 |

## 3. 儿童交互屏

| 状态 | 需求 |
| -- | -- |
| 已确认 | 展示课程、题目、答案、提示和训练进度。 |
| 已确认 | 支持当前 `matching` 和 `ordering` 课程基线。 |
| 当前推测 | 提供显式语音状态、网络状态和会话恢复提示。 |
| 待确认 | 是否允许儿童查看完整报告，还是只给老师/家长查看。 |

## 4. 机器人表情屏

| 状态 | 需求 |
| -- | -- |
| 已确认 | 展示待机、倾听、思考、回答、答对表扬、答错鼓励等动画。 |
| 已确认 | 本项目只负责动画调用、状态衔接和时序控制，不重新制作动画资源。 |
| 当前推测 | 表情屏不承担判题、课程推进或报告计算职责。 |
| 待确认 | 动画资源是 CSS、视频、Lottie、图片序列、Unity/机器人 SDK 还是其他形式。 |

## 5. 真实语音

| 状态 | 需求 |
| -- | -- |
| 已确认 | 后续必须支持真实语音交互，而不是主要依赖文字输入。 |
| 已确认 | 链路需覆盖音频采集、VAD、STT、上下文、LLM、审核、TTS、播放、动画同步、超时、重试和降级。 |
| 当前推测 | 每次语音交互应有 `turnId`、取消信号、幂等键和可观测事件。 |
| 待确认 | STT/TTS/LLM 供应商、是否启用流式、语音由哪个屏幕播放。 |

## 6. 注意力检测

| 状态 | 需求 |
| -- | -- |
| 已确认 | 训练过程需要检测和记录注意力相关指标。 |
| 当前推测 | 第一阶段只记录可追溯的任务参与事件，如无操作时长、离屏、题间停顿、摄像头 Mock 事件。 |
| 当前推测 | 报告中优先使用“任务参与度/响应稳定性”，避免无依据的临床注意力评分。 |
| 待确认 | 注意力定义、硬件输入、算法、阈值和是否保存原始视频。 |

## 7. 语言表达检测

| 状态 | 需求 |
| -- | -- |
| 已确认 | 训练过程需要检测和记录语言表达。 |
| 当前推测 | 先基于语音转写和聊天文本记录儿童消息数、平均长度、求助词、挫败表达、主动提问。 |
| 待确认 | 语言表达能力的正式定义、评分规则、年龄段差异和禁用措辞。 |

## 8. 评估报告

| 状态 | 需求 |
| -- | -- |
| 已确认 | 最终报告会包含比当前 Demo 更多指标和标准。 |
| 已确认 | 当前专业报告中的演示常模、百分位和专家建议不能直接作为正式评估标准。 |
| 当前推测 | 报告应分为原始观测、特征、指标、规则版本、解释文案和安全审核结果。 |
| 待确认 | 报告是否具有专业评估含义、谁查看、是否导出、是否需专家审核。 |

## 9. 大模型

| 状态 | 需求 |
| -- | -- |
| 已确认 | 机器人语音回复和报告文案需要接入大模型 API。 |
| 已确认 | LLM 不应自由生成核心定量分数。 |
| 当前推测 | 主模型只生成候选回复或报告解释，输出必须经过审核后播放或展示。 |
| 待确认 | 供应商、模型、成本预算、数据是否允许出域、失败固定回复。 |

## 10. 内容安全

| 状态 | 需求 |
| -- | -- |
| 已确认 | 面向儿童，LLM 输出播放或展示前必须独立安全审核。 |
| 已确认 | 审核可组合确定性规则、敏感信息检查、审核模型、适龄性审核和固定兜底。 |
| 当前推测 | 输入也应审核和脱敏，避免隐私、危险内容和 Prompt 注入进入主模型。 |
| 待确认 | 审核模型是否可接收原文、审核超时预算、人工介入策略。 |

## 11. 数据与隐私

| 状态 | 需求 |
| -- | -- |
| 已确认 | 原始音视频是否保存必须成为显式配置和产品决策。 |
| 当前推测 | 默认不保存原始音视频，只保存低粒度事件和聚合指标。 |
| 当前推测 | 需要删除、脱敏、导出和保留期限接口边界。 |
| 待确认 | 儿童姓名、对话、音频、视频、行为日志和报告的保留时间。 |

## 12. 非功能需求

| 状态 | 需求 |
| -- | -- |
| 当前推测 | 双屏状态同步依赖后端事件，不能只依赖前端本地状态。 |
| 当前推测 | 核心接口和事件需要幂等，支持刷新、重连和重复提交。 |
| 当前推测 | 语音链路应有超时预算、Mock、降级和成本控制。 |
| 待确认 | 最大可接受交互时延、局域网/公网、认证、设备身份和验收环境。 |

## 13. 当前范围外

- 不实现新的业务功能。
- 不重构现有业务代码。
- 不接入真实外部付费 API。
- 不制作或修改动画资源。
- 不自行定义正式专业评分、常模、诊断或治疗建议。
- 不写入真实 API Key。

## 14. 待确认需求汇总

1. 双屏硬件形态和部署拓扑。
2. 前端形态选择：一个 Vite 应用两个页面，还是两个独立前端应用。
3. 动画资源技术形态、manifest 和回调能力。
4. 麦克风、摄像头、扬声器和机器人协议。
5. STT/TTS/LLM/审核供应商和数据出域边界。
6. 是否保存原始音频、视频和聊天原文。
7. 注意力与语言表达的正式指标定义。
8. 报告使用者、专业含义和导出策略。
9. 最大交互时延和模型失败固定回复。
10. 是否允许儿童打断机器人语音。
