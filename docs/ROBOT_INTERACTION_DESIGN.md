# 机器人双屏交互设计规范

> 版本：1.0（2026-07-18）
> 定位：机器人课程交互的核心行为规范。本文只规定事件、双屏、表情、动作和语音的协作方式，不改变课程数据、课程素材和课程选音规则。

## 1. 双屏职责

| 区域 | 唯一职责 | 不应承担的职责 |
|---|---|---|
| 上屏（机器人脸屏） | 表达情绪、注视方向和交互状态；行为表情单次播放后回待机 | 不展示题目、答案、长文字或课程操作按钮 |
| 下屏（儿童课程屏） | 持续呈现当前课程目标、图片、视频或互动页面；必要时叠加短反馈层 | 不长期播放与当前任务无关的庆祝内容，不因为表情切换重新加载课程 |
| 机械动作 | 强化“提问、提示、鼓励、问候、告别”的语义 | 不替代语音，不连续大幅摆动，不跨过表情主时间轴 |
| 课程语音 | 由课程系统按课程、课点和事件动态选择内容 | 不绑定到动作文件；动作绑定只保存 `audio.offsetMs` |

## 2. 统一时间轴

所有正式行为以收到一个语义明确的 `play_resource.aux` 事件为起点：

| 时间点 | 行为 |
|---|---|
| `T0` | 上屏行为表情从首帧开始；保持下屏当前课程上下文 |
| `T0 + motionOffsetMs` | 启动动作 JSON；使用 JSON 自带初始姿态、时间点和回中位命令 |
| `T0 + audio.offsetMs` | 播放课程系统为本次事件选出的语音 |
| `T0 + expressionDurationMs` | 行为表情仅结束一次，立即露出已在底层持续播放的待机表情；不会为等待动作而重播 |
| `T0 + eventDurationMs` | 事件互斥结束；其中 `eventDurationMs = max(表情时长, 动作偏移 + 实际命令跨度)` |
| 行为结束后 | 延迟回待机姿态；此后才接受下一次点击 |

约束：

- 表情和动作时长相互独立：表情必须完整播放一次，动作必须按偏移完整执行；任一较长都会延长事件占用，但不会拉长或循环另一方。
- 动作结束点按最后一条实际命令的 `time + moveMs` 计算；导入 JSON 的总时长可以保留静止尾段，但不再限制替换表情。
- `audio.offsetMs < expressionDurationMs`。语音文件由课程动态选择，因此语音时长不写入动作绑定。
- 表情结束不能截断语音；若某条课程语音更长，上屏按时回待机，语音自然播完。
- 同一行为表情不循环、不强制刷新下载、不在结尾额外插入空白帧。
- 当前事件占用期间，新的 `play_resource` 直接失效：不播放语音、不切换上下屏、不执行动作，也不进入等待队列。

## 3. 核心交互设计表

表内“下屏建议”是呈现规则，不修改课程源内容。涉及叠加层时，应覆盖在当前课程内容之上，并在结束后露出原内容。

| 事件触发时机 | 事件/槽位 | 上屏表情资源 | 下屏内容 | 表情应该是什么样 | 动作应该是什么样 | 语音与建议偏移 | 建议总时长 | 切换与失败回退 |
|---|---|---|---|---|---|---|---|---|
| 页面启动、尚未进入课程、行为序列结束 | `idle` | 当前 `v2_idle.gif` | 待机页；进入课程后保持当前课点 | 平静、友好、低刺激；自然眨眼和轻微呼吸感，首尾帧一致 | `空动作`或幅度极小的待机姿态；不持续摆臂 | 无课程语音 | 持续循环 | 待机 GIF 永久在底层运行；任何行为结束直接露出，不重新请求文件 |
| 教师进入控制页、儿童端进入准备阶段 | 准备/就绪（建议新增 UI 状态，不新增课程内容） | `v2_expectant.gif`，只播一次后待机 | 保持准备页，明确显示摄像头、录音、声音是否就绪 | 期待但安静，眼神集中，不做夸张惊讶 | 轻微抬头或身体朝向儿童；不要挥手 | 系统就绪提示可选；不复用课程问句 | 2.0–2.5 秒 | 声音未解锁时优先显示“点击启用声音”，不开始正式课点 |
| 教师打开一个普通课点，但没有提问/提示/表扬标志 | `silent` | `v2_idle.gif` | 加载并保持课程图片、视频或互动页 | 不抢注意力，保持待机 | 默认不执行动作 | 无行为语音 | 0 秒行为；只切下屏内容 | 当前实现应跳过“无动作 + 待机表情”的空序列，避免占用 3 秒队列 |
| 课程目标已在下屏稳定显示，需要机器人提出问题 | `question` | 当前 `v2_curious.gif` | 保持当前目标；可短暂加柔和聚焦边框，但不能遮住目标 | 好奇、专注、鼓励回答；避免皱眉形成压力 | 轻微前倾或歪头，单手向目标方向做开放式引导，随后回中位 | 课程动态问题语音；建议 `200–500ms`，先让儿童看到表情再听到问题 | 以表情素材为准，当前约 3.0 秒 | 不重载下屏内容；语音失败时表情和动作仍完整执行，教师端显示错误状态 |
| 问题语音结束，等待儿童回答 | 等待回答（设计状态） | 回到 `v2_idle.gif`，未来可增加低刺激 listening 表情 | 目标持续可见，不弹出答案 | 专注、耐心、少眨眼；不制造催促感 | 保持中立姿态，不重复提问动作 | 不自动重复语音 | 由课程/教师控制 | 等待状态不能触发随机表情；超时后才进入提示事件 |
| 儿童暂未作答、注意力下降或教师点击提示 | `hint` | 当前 `v2_curious.gif`；若强调“看这里”可用 `v2_expectant.gif` | 保持当前目标；只高亮关键区域或显示课程原有提示，不揭示完整答案 | 温和提醒、方向明确，不显失望 | 当前 `05-吸引注意01`：小幅招手或指向下屏；动作一次后回中位 | 课程动态提示语音；建议 `300–700ms`，动作先建立注意方向 | 当前约 3.0 秒；必要时选择更长表情 | 同一题连续提示建议至少间隔 2 秒；加载不到课点提示语音时按现有规则回退课型提示语音 |
| 儿童完成目标、分析判定成功或教师点击表扬 | `praise` | 当前 `v2_happy.gif` | **推荐：保留当前课程目标，叠加 1.2–1.8 秒轻量成功反馈**（星星、对勾、柔和彩带），随后自动消失；不应长时间替换成无关视频 | 清晰开心、温暖认可；笑容应从自然到明显再自然收回，首尾一致 | 当前 `03-表扬`：抬臂/点头式肯定，幅度中等，最多一次主动作并回中位 | 课程动态表扬语音；建议 `100–350ms`，接近表情和动作起点 | 当前约 4.27 秒 | 当前系统可播放表扬视频；产品目标建议将其作为可配置短叠加，不阻塞下一课点。视频失败时保留下屏原目标，不显示黑屏 |
| 儿童回答错误，但仍可继续尝试 | retry（当前可由 `hint` 承担，未来可独立槽位） | 建议新增温和鼓励表情；现有资源优先 `v2_expectant.gif` | 保持题目与已操作结果；只撤销错误高亮或提示再试一次 | 鼓励、无否定感；不能使用明显摇头或悲伤表情 | 当前 `04-摇头再来一次`若幅度明显，应降低摇头次数；更推荐轻点头后开放式手势 | 课程“再试一次”语音；建议 `250–500ms` | 2.5–3.5 秒 | 不清空儿童已完成的正确部分；连续错误后切换到 `hint`，不要无限重复同一动作 |
| 社交课程进入“初次见面/打招呼”步骤 | `social_greeting_intro` | 当前 `v2_happy.gif` | 保持社交课程人物/情境图，不切到独立动画 | 开朗、主动但不过度兴奋，目光朝向儿童 | 当前 `01-打招呼`：一次完整挥手序列，动作 JSON 内两次挥手可保留并完整回中位 | 课程动态打招呼语音；建议根据动作 JSON 微调到首次抬手前后，通常 `200–600ms` | 以表情时长为主，且必须覆盖完整挥手动作 | 第一次触发也必须立即入队；不得由空 `silent` 序列延迟。结束直接回待机脸 |
| 社交课程邀请一起互动/玩耍 | `social_greeting_play` | 当前 `v2_expectant.gif` | 保持当前社交情境；可出现课程原有的“轮到你”指示 | 期待、开放、给儿童留出回应空间 | 双手轻张或单手邀请，动作落点面向儿童，避免连续挥手 | 课程动态邀请语音；建议 `250–500ms` | 2.5–3.5 秒 | 语音结束后进入等待回答，不自动重复邀请 |
| 社交课程由机器人先说再见 | `social_farewell_bye` | 当前 `v2_shake_head.gif`；**未来建议补充专用温暖告别表情** | 保持告别情境或课程结束卡，不提前跳回首页 | 温暖、舒缓；不应像否定或拒绝 | 当前 `07-再见`：慢速挥手 1–2 次，幅度小于打招呼并完整回中位 | 课程动态告别语音；建议 `150–450ms` | 2.7–4.0 秒 | 若 `shake_head` 视觉像否定，应换专用 goodbye 素材，而不是修改课程语音 |
| 儿童说再见后机器人回应 | `social_farewell_reply` | 同告别表情 | 保持结束卡；语音结束后再允许教师结束课程 | 回应感强于主动告别，表情起势可更快 | 简短单次挥手或轻点头，不重复完整长动作 | 课程动态回应语音；建议 `100–300ms` | 2.5–3.5 秒 | 与上一告别事件间隔不足时进入队列，不重叠播放 |
| 配对/排序等互动页答对 | 互动成功事件 + `praise` 视觉语义 | `v2_happy.gif` | 保留互动页结果，正确项高亮；短成功叠加后进入下一题 | 开心但短促，减少打断操作节奏 | 可使用简化表扬动作，避免每小步都播放完整大动作 | 继续使用互动课程自己的动态表扬语音 | 1.5–3.0 秒 | 小步骤成功与整题完成应分级：小步骤只做下屏反馈，整题完成才触发完整机器人行为 |
| 配对/排序操作错误 | 互动错误/提示语义 | `v2_curious.gif` 或待机 | 保留当前操作状态，错误项轻微回弹，不展示红色大叉覆盖全屏 | 中性好奇，不表达责备 | 默认不做大动作；达到提示条件才执行吸引注意动作 | 由互动课程现有规则决定，不新增固定语音 | 0.5–2.0 秒 | 高频操作事件必须节流，不能每次拖拽错误都排一个完整行为 |
| 60 秒无正式交互且当前确实空闲 | 自动表情 | 从非待机素材中低频随机选择 | 下屏保持当前内容或待机页 | 只用于“有生命感”，不可与问题、等待回答、提示同时发生 | 默认无动作 | 无语音 | 单次素材时长 | 正式行为优先；随机事件不得插到正式行为队列前，也不能延迟提问 |
| 浏览器拒绝自动播放 | 音频恢复状态 | 已触发的行为表情照常；之后回待机 | 显示“请点击屏幕解锁声音”，覆盖层仅用于恢复声音 | 不新增错误/悲伤表情，避免儿童认为自己答错 | 当前动作可完成；不重复动作 | 保留被拦截的原课程语音，点击后重试；不重新随机选音 | 直到点击 | `stop_audio` 或切换课程时清除过期待恢复项；错误详情回传教师端与日志 |
| Robot Runtime 离线、动作启动失败 | 降级状态 | 表情仍完整播放一次 | 课程内容和语音照常，不弹出技术错误给儿童 | 保持原表情 | 跳过动作；不得反复重试导致舵机抖动 | 课程语音照常 | 原表情时长 | 教师端/监控台记录 Runtime 离线；儿童体验降级为“表情 + 语音” |

## 4. 表情素材设计要求

| 项目 | 规范 |
|---|---|
| 首尾帧 | 完全一致或视觉差异极小，以便行为层结束后自然露出待机层 |
| 循环 | 待机可循环；行为表情只按单次时长播放一次 |
| 时长 | 常规 2.5–4.5 秒；高频微反馈 1.2–2.0 秒；不建议超过 5 秒 |
| 运动幅度 | 表扬最高，问候次之；提问/提示中等；等待和待机最低 |
| 情绪强度 | 儿童友好、明确但不夸张；错误反馈不使用愤怒、明显失望或强烈摇头 |
| 文件策略 | 启动后后台预加载；事件切换不追加时间戳；异步加载结果必须校验是否仍属于当前事件 |
| 命名建议 | `v2_idle`、`v2_happy`、`v2_curious`、`v2_expectant`、未来增加 `v2_listening`、`v2_encourage`、`v2_goodbye` |

## 5. 动作设计要求

| 项目 | 规范 |
|---|---|
| 数据来源 | 以导入的 DollSer motion JSON 为准，保留 `initialPose`、`commands`、`motionStartTime`、`motionDurationMs` |
| 回中位 | 每个主动作必须有平滑 return phase；行为结束前完成，不依靠下一动作纠正姿态 |
| 幅度 | 儿童近距离使用时优先中小幅；左右臂避免同时快速大幅运动 |
| 次数 | 提问、提示、表扬主动作通常一次；挥手最多 1–2 次；高频互动小步骤默认不触发完整动作 |
| 速度 | 起步和回中位不突跳；动作 JSON 的 `moveMs` 不应被运行时随意覆盖 |
| 冲突 | 所有正式动作串行；待机动作启动前保留延迟，新行为到来时取消或停止待机动作 |
| 失败降级 | 动作失败不重复轰炸 Runtime，不阻塞表情和课程语音 |

## 6. 下屏反馈层建议

“表扬时显示什么”建议采用保留课程上下文的短叠加层：

| 反馈级别 | 触发 | 下屏呈现 | 时长 | 是否触发完整表情/动作/语音 |
|---|---|---|---|---|
| 操作级成功 | 配对成功一个卡片、排序放对一步 | 正确项绿色/金色描边，小星光或轻回弹 | 0.4–0.8 秒 | 否；避免行为队列爆满 |
| 课点级成功 | 完成一道题或教师点击表扬 | 当前目标上叠加对勾、星星和柔和彩带；背景课程内容仍可辨认 | 1.2–1.8 秒 | 是，走 `praise` 完整序列 |
| 阶段级完成 | 完成一个课程阶段 | 完成卡 + 本阶段成果摘要；由教师确认进入下一阶段 | 2–4 秒 | 可触发一次完整表扬，不连续叠加多次 |

现有随机表扬视频可以保留为可配置模式，但建议满足：预加载、静音或不与课程语音争抢、最长不超过行为表情时长、播放失败立即露出原课程内容。

## 7. 事件优先级与队列策略

| 优先级 | 事件 | 策略 |
|---|---|---|
| P0 | 停止课程、紧急停止动作、声音解锁 | 立即处理；清理未开始的延迟音频和过期待恢复项 |
| P1 | 正式提问、社交问候/告别、教师主动触发 | 空闲时立即执行；忙碌时本次点击直接失效，不排队 |
| P2 | 表扬、提示、再试一次 | 空闲时立即执行；播放期间的重复点击直接失效 |
| P3 | 自动随机表情、待机动作 | 仅队列为空时执行；任何正式事件到来立即让路 |

## 8. 验收清单

| 验收项 | 通过标准 |
|---|---|
| 首次打招呼 | 第一次与后续触发的表情、动作、语音起点差异不超过可感知范围；无 3 秒空序列 |
| 表情次数 | 每个正式事件行为表情只播一遍，随后无闪白、无旧 GIF 回盖，立即回待机 |
| 动作完整性 | 动作不被下一事件或待机动作抢占；结束前回中位 |
| 语音归属 | 每次文件仍由课程系统选择；动作绑定只影响开始偏移 |
| 语音恢复 | 浏览器拦截时有明确解锁层，点击后播放原语音，不重新随机选择 |
| 下屏连续性 | 提问、提示不重新加载课程；表扬反馈结束后原课程内容仍在 |
| 快速连点 | 第一条行为完整执行；期间后续点击全部失效，等待队列始终为空 |
| 配置保存 | 并发读取时始终得到完整 JSON；保存失败能返回错误，不留下半文件 |
| Runtime 离线 | 课程内容、表情和语音可继续，动作安全降级且错误可观测 |
