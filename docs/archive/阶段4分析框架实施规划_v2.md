# 阶段4：分析框架实施规划（v2 - 增强版）

## 一、需求分析

### 三类分析场景

根据你的需求，分析系统需要支持三类不同的分析场景：

| 类型 | 名称 | 特点 | 典型场景 |
|------|------|------|----------|
| **Type A** | 实时分析+控制 | 逐帧/逐块分析，与目标比对，达到阈值自动控制 | 姿态模仿、语音命名 |
| **Type B** | 滑动窗口分析 | 周期性分析过去N秒数据，触发干预 | 注意力检测 |
| **Type C** | 会话汇总分析 | 会话结束后统计，生成报告 | 总字数、整体注意力 |

### Type A：实时分析+控制（姿态模仿、语音命名）

```
流程：
1. 设置目标（目标图片姿态 / 目标语音）
2. 实时接收儿童端数据
3. 与目标比对，计算匹配度/准确率
4. 将结果实时推送给教师端
5. 达到阈值（如95%）→ 自动控制儿童端（播放表扬）

关键能力：
- 目标设置（Target）
- 实时比对（Matcher）
- 阈值判断（Threshold）
- 自动控制（Trigger/Action）
```

### Type B：滑动窗口分析（注意力检测）

```
流程：
1. 持续缓存过去10秒的视频+音频数据
2. 每1秒触发一次分析
3. 模型读取缓存数据，综合分析姿态、眼动等
4. 输出过去10秒的注意力评分
5. 低于阈值 → 触发干预（播放感兴趣内容）

关键能力：
- 数据缓冲（Buffer）
- 定时触发（Scheduler）
- 窗口分析（WindowAnalyzer）
- 阈值触发（Trigger）
```

### Type C：会话汇总分析（课程结束统计）

```
流程：
1. 在整个会话期间累积统计数据
2. 会话结束时生成汇总报告
3. 输出：总字数、平均注意力、关键事件等

关键能力：
- 累积器（Accumulator）
- 统计计算（Statistics）
- 报告生成（ReportGenerator）
```

## 三、核心组件设计

### 1. 分析模式枚举

```python
class AnalysisMode(Enum):
    """分析模式"""
    REALTIME = "realtime"           # Type A: 实时分析+控制
    WINDOW = "window"               # Type B: 滑动窗口分析
    SESSION = "session"             # Type C: 会话汇总分析
```

### 2. 分析器基类（增强版）

```python
class BaseAnalyzer(ABC):
    """分析器基类（增强版）"""
    
    @property
    @abstractmethod
    def mode(self) -> AnalysisMode:
        """返回分析模式"""
        pass
    
    @abstractmethod
    def analyze(self, data: Any, context: AnalysisContext) -> AnalysisResult:
        """执行分析"""
        pass
    
    # 可选：支持目标比对
    def set_target(self, target: Any) -> None:
        """设置比对目标（Type A 使用）"""
        pass
    
    def compare_with_target(self, data: Any) -> float:
        """与目标比对，返回匹配度 0-1（Type A 使用）"""
        pass
```

### 3. 比对器接口（新增）

```python
class BaseMatcher(ABC):
    """比对器基类 - 用于 Type A 实时分析+控制"""
    
    @abstractmethod
    def set_target(self, target: Any) -> None:
        """设置比对目标"""
        pass
    
    @abstractmethod
    def match(self, data: Any) -> MatchResult:
        """执行比对，返回匹配结果"""
        pass

@dataclass
class MatchResult:
    """匹配结果"""
    score: float                    # 匹配度 0-1
    details: Dict[str, Any]         # 详细信息
    passed: bool                    # 是否达到阈值
    threshold: float                # 使用的阈值
```

### 4. 数据缓冲区（新增）

```python
class DataBuffer:
    """滑动窗口数据缓冲区 - 用于 Type B 窗口分析"""
    
    def __init__(self, window_size: float = 10.0):
        """
        Args:
            window_size: 窗口大小（秒）
        """
        self.window_size = window_size
        self.video_buffer: Deque[Tuple[float, np.ndarray]] = deque()
        self.audio_buffer: Deque[Tuple[float, bytes]] = deque()
    
    def add_video_frame(self, timestamp: float, frame: np.ndarray) -> None:
        """添加视频帧"""
        pass
    
    def add_audio_chunk(self, timestamp: float, chunk: bytes) -> None:
        """添加音频块"""
        pass
    
    def get_window_data(self) -> WindowData:
        """获取当前窗口数据"""
        pass
    
    def _cleanup_old_data(self) -> None:
        """清理窗口外的旧数据"""
        pass
```

### 5. 累积器（新增）

class Accumulator:

### 6. 触发系统（新增 - 核心）

```python
class TriggerSystem:
    """触发系统 - 管理阈值判断和自动控制"""
    
    def __init__(self, socketio: SocketIO):
        self.socketio = socketio
        self.triggers: Dict[str, Trigger] = {}
    
    def register_trigger(self, trigger: Trigger) -> None:
        """注册触发器"""
        pass
    
    def check_and_execute(self, result: AnalysisResult) -> Optional[Action]:
        """检查结果并执行触发的动作"""
        pass

@dataclass
class Trigger:
    """触发器定义"""
    name: str
    condition: Callable[[AnalysisResult], bool]  # 触发条件
    action: Action                                # 触发动作
    cooldown: float = 3.0                        # 冷却时间（避免频繁触发）

@dataclass  
class Action:
    """动作定义"""
    action_type: str              # 动作类型: "play_audio", "emit_event", etc.
    target: str                   # 目标: "child", "therapist", "both"
    payload: Dict[str, Any]       # 动作参数
```

## 十、总结

### 增强后的核心能力

1. ✅ **Type A - 实时分析+控制**
   - Matcher比对器
   - 阈值判断
   - 自动触发动作（播放表扬）

2. ✅ **Type B - 滑动窗口分析**
   - DataBuffer数据缓冲
   - 定时触发分析
   - 注意力干预

3. ✅ **Type C - 会话汇总分析**
   - Accumulator累积器
   - 会话报告生成

4. ✅ **统一的触发系统**
   - 可配置阈值
   - 灵活的动作定义
   - 支持冷却时间

### 设计原则

- **模式分离**：三类分析场景独立处理
- **可配置性**：阈值、窗口大小等可配置
- **可扩展性**：易于接入真实模型
- **松耦合**：分析和控制分离，通过事件通信
