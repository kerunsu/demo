# 儿童教育互动训练 Demo - PRD（MVP）

## 1. 项目背景与目标

本项目目标是构建一个面向儿童、可独立操作、可完整演示的互动训练系统 MVP。  
系统需支持儿童从进入页面到完成训练并生成评估报告的全流程闭环，优先保证流程正确性与稳定性，再逐步增强智能能力。

## 2. 目标用户

- 主要用户：6-10 岁儿童（可独立点击和阅读简单提示）
- 次级用户：演示者/开发者（用于启动系统与查看结果）

## 3. MVP 范围（必须完成）

### 3.1 页面闭环

页面流程固定为：

1. 欢迎页
2. 课程选择页
3. 课程进行页
4. 结果/报告页

要求：儿童可自主完成整个流程，无需后台角色介入。

### 3.2 课程模块（两类）

先实现两类课程：

- 配对（Matching）
- 排序（Ordering）

每类课程必须支持：

- 题目展示
- 作答交互
- 即时反馈（正确/错误）
- 自动进入下一题

### 3.3 自动流程控制

系统内置简单规则引擎（不做后台配置），例如：

- 连续错误 2 次触发提示
- 单题正确后自动鼓励并进入下一题
- 单题超时触发温和提醒

### 3.4 轻量自然语言交流

- 儿童输入一句文本（MVP 不做语音）
- 系统返回简短回应（规则 + 模板）
- 对话实现为独立 service，预留可替换接口

### 3.5 评估报告

课程完成后自动生成结构化报告，至少包含：

- 完成时间
- 题目总数/正确数/正确率
- 平均响应时长
- 错误类型统计
- 对话交互摘要（简版）

## 4. 非目标（本阶段不做）

- 账号体系、权限体系、多角色后台
- 高精度语音识别和复杂模型推理优化
- 推荐系统和长期学习画像
- 复杂运维部署体系

## 5. 关键产品原则

- 以可演示闭环为优先，不做大而全
- 儿童端界面简洁、低认知负担
- 先流程稳定，后能力增强
- 所有交互以儿童独立操作为前提

## 6. 功能验收标准

1. 本地可一键启动并演示完整流程
2. 儿童端可独立完成从进入到报告生成
3. 两类课程均可运行
4. 报告字段完整且稳定生成
5. 对话模块可响应简单自然语言输入
6. 文档齐全，可交接

## 7. 技术栈建议（先定后做）

### 7.1 前端建议：React + TypeScript + Vite

理由：

- Vite 启动快，适合 Demo 快速迭代
- React 生态成熟，页面状态机和组件化清晰
- TypeScript 有利于约束课程题目、报告结构和接口模型

### 7.2 后端建议：Node.js + Express + TypeScript

理由：

- 与前端同语言，开发和交接成本低
- Express 足够支撑 MVP 接口和会话逻辑
- 便于快速拆分 service（课程、对话、报告）

### 7.3 存储建议（MVP）：内存 + JSON 文件落盘

理由：

- 无需引入数据库即可跑通闭环
- 支持保存会话和报告用于演示回放
- 后续可平滑替换为 SQLite/PostgreSQL

## 8. 分阶段实施

### Phase 1：产品与技术设计

- 完成 `PRD/ARCHITECTURE/FLOW/API/REPORT_SCHEMA` 文档
- 确认页面原型与状态机

### Phase 2：最小闭环开发

- 实现欢迎页/选课页/课程页/报告页
- 先打通 1 种课程 + 报告生成

### Phase 3：MVP 完整化

- 增加第 2 种课程
- 接入轻量对话能力
- 完成错误处理、基础日志、README

### Phase 4：验收与演示

- 提供完整演示步骤
- 记录已知问题与下一阶段建议

## 9. 风险与缓解

- 风险：课程交互过复杂导致儿童误操作  
  缓解：单页只保留必要动作按钮，减少分支

- 风险：规则对话显得僵硬  
  缓解：先保证可用，统一由对话服务管理，后续替换模型

- 风险：纯内存数据丢失  
  缓解：关键报告落盘保存
